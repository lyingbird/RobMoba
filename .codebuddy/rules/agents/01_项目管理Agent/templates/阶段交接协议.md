# 📤 阶段交接协议（Handoff Protocol）

> 解决全流程在单一会话中执行导致上下文爆炸的问题。
> 在预设断点处生成结构化交接摘要，使下一段可在新会话/compact后快速恢复。
> 版本: v1.0 | 创建: 2026-03-18

---

## 🎯 核心思路

```
旧模式: [制作人→PM→策划→UX→主程→程序→QA→交付] = 1个超长会话，上下文爆炸
新模式: [设计段] → 交接 → /compact → [实现段] → 交接 → /compact → [验收段]
```

**每段独立执行**，段间通过 `handoff.md` 文件传递关键信息，避免累积无用的对话历史。

---

## 📏 断点规则

### FEATURE / FEATURE_UI 标准断点（3段式）

| 段 | 包含阶段 | 上下文特征 | 建议时机 |
|---|---------|-----------|---------|
| **设计段** | 制作人→PM→策划→[UX→策划确认]→主程 | 文档读写为主，代码极少 | 主程完成技术设计后 |
| **实现段** | 程序Agent（编码+门禁+对抗审查） | 代码密集，文件读写量最大 | 程序Agent对抗审查完成后 |
| **验收段** | QA→策划交付→PM完成 | 验证+文档更新 | 流程结束 |

### 其他需求类型断点

| 类型 | 建议分段 | 说明 |
|------|---------|------|
| OPTIMIZE | 设计段(PM→主程) + 实现段(程序+QA+交付) | 2段即可 |
| BUGFIX | 通常不分段 | 流程短，1段完成 |
| CONFIG | 通常不分段 | 流程短，1段完成 |
| RESEARCH | 不分段 | 无编码 |

### 动态断点（编码任务过多时）

当程序Agent编码任务 ≥ 5个 时，实现段内部可再分段：
- **实现段-A**: 编码任务 T1~T3 + 中间compact
- **实现段-B**: 编码任务 T4~T7 + 门禁 + 对抗审查

## 📄 交接摘要模板

> 每段结束时，由**当前最后一个Agent**写入 `.GameDev/REQ-XXX/handoff.md`

```markdown
---
req_id: REQ-XXX
req_name: {需求名称}
req_type: FEATURE
req_scale: M
handoff_version: 1
created_at: {时间戳}
from_segment: 设计段
to_segment: 实现段
---

# 📤 阶段交接摘要

## 已完成阶段
- ✅ 制作人 → 需求分类: FEATURE_UI, 规模: M
- ✅ PM → REQ-XXX 已初始化
- ✅ 策划 → 01_策划案.md 完成, AC共X条
- ✅ UX → 02_UX设计.md 完成
- ✅ 策划确认 → UX方案通过
- ✅ 主程 → 03_技术设计.md 完成, 任务X个

## 下一段待执行
- 程序Agent → step-01 前置检查 开始

## 核心输入文件（下段必读）
| 文件 | 读取范围 | 说明 |
|------|---------|------|
| `01_策划案.md` | AC列表部分 | 验收标准对照 |
| `03_技术设计.md` | 完整阅读 | 架构+接口定义 |
| `05_任务清单.md` | 完整阅读 | 编码任务卡片 |

## 关键决策记录（3-5条，影响后续实现的决策）
1. {决策1: 例如选用了什么架构方案}
2. {决策2: 例如选用了什么技术方案}
3. {决策3: 例如哪些地方做了trade-off}

## 已知风险/待注意（对抗审查/QA需关注）
- {风险1}
- {风险2}

## 不需要的上下文（明确排除，避免下段误读）
- ❌ 策划方案讨论过程
- ❌ UX交互细节（除非编码涉及UI布局）
- ❌ 制作人分类推理过程
```

## 🔄 恢复流程（下段开始时）

### 自动恢复（推荐）

用户说 `"继续 REQ-XXX"` 或 `"/gd:resume REQ-XXX"` 时：

1. 读取 `REQ-XXX/handoff.md` → 获取 `to_segment` 和 `核心输入文件`
2. 读取 `01_策划案.md` 的 frontmatter → 确认 `current_agent` 和 `current_step`
3. **只读取**交接摘要中列出的`核心输入文件`（不读取其他历史文件）
4. 加载对应Agent入口文件 + 步骤文件
5. 输出恢复确认后继续执行

### 恢复确认输出格式

```
📤 从交接摘要恢复：
- 需求: REQ-XXX {需求名称}
- 已完成段: 设计段 (制作人→PM→策划→UX→主程)
- 当前段: 实现段
- 关键决策: {列出3条}
- 已知风险: {列出}
- 核心文件已加载: ✅

继续执行 程序Agent step-01...
```

---

## ⚡ 执行规则

1. **段内不交接**: 同一段内的Agent切换不需要写交接摘要，正常流转即可
2. **段末必交接**: 到达断点时，当前Agent在执行完本阶段任务后，追加写入 `handoff.md`
3. **交接后 compact**: 写完交接摘要后，建议执行 `/compact` 或开始新会话
4. **交接文件累加**: `handoff.md` 每段追加新版本（handoff_version +1），不覆盖旧版本
5. **交接不替代 frontmatter**: frontmatter 状态追踪正常维护，交接摘要是额外的上下文优化层
