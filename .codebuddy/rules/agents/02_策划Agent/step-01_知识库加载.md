# Step 01: 知识库加载 [MODE: EXPLORE]

## 📍 当前位置
步骤 1/6 | 前置：接收到用户需求 | 后续：需求分析 | 🧭 探索模式

## 🎯 本步骤目标
加载策划阶段需要的知识和上下文信息，为后续设计奠定基础。

## 📋 执行清单

### 1.1 领域知识按需加载（🗜️ 索引路由，非全量）

> **核心规则**：通过领域知识索引按需加载，**禁止全量读取全局策划案/全局技术文档**。

**加载步骤**：
1. □ **提取需求关键词**（从用户原文中提取功能名、模块名、系统名等）
2. □ **读取领域知识索引** `rules/skills/domain-index.md`（匹配关键词→领域模块）
3. □ **只加载命中的领域模块**（通常 1-3 个 `domain-*/` 文件）
4. □ 如有需要，加载相关技术 Skill 文件（S1-S11）
5. □ 如果领域模块不够详细 → 再回退读取全局文档的**对应章节**

```
📦 按需加载示例：
需求："摇杆在英雄选择时不应该能移动"
→ 提取关键词：摇杆、移动、英雄选择
→ 索引匹配：D3(移动与输入) ✅ + D4(UI组件) ✅ + D7(游戏流程) ✅
→ 加载：domain-movement/input-movement-system.md + domain-ui/ui-components.md + domain-gameflow/game-flow.md
→ 跳过：D1战斗、D5通信、D6经济 ⏭️
→ 总加载量：~300行（vs 旧方式全量 ~1600行）
```

**加载清单**：
| # | 知识源 | 加载方式 | 说明 |
|---|--------|---------|------|
| 1 | 领域知识索引 | 📖 全量读取 | `rules/skills/domain-index.md` — 关键词匹配入口 |
| 2 | 命中的领域模块 | 📖 全量读取 | 通常 1-3 个 `domain-*/` 文件，每个 60-120行 |
| 3 | 相关 Skill 文件 | 🗜️ 按需加载 | 如涉及技能实现→S2、涉及通信→S1 |
| 4 | 入口文件禁止事项 | 📖 快速浏览 | 已在step加载前读过 |

### 1.2 补充阅读（仅在领域模块不足时）

6. □ **如需更多细节** → 读取全局策划案的**对应章节**（非全量）
7. □ **检查成功模式库** — 快速扫描是否有可复用的设计模式

## 📝 输出要求
- 在脑中建立项目全景图：已有哪些功能、新需求和哪些功能关联
- 如果成功模式库中有可复用的设计，记下来在方案设计步骤中应用
- **标注本次实际加载了哪些知识库章节**（便于追溯和迭代优化加载规则）

## ⚠️ 本步骤常见陷阱
- ❌ 跳过知识库直接开始设计，导致重复造轮子
- ❌ 不看全局策划案，导致设计与现有功能冲突
- ❌ 忽略成功模式库中可复用的设计
- ❌ **全量加载所有知识库**（浪费token，应精准加载）
- ❌ **不确定时跳过知识库**（不确定时应全量加载，宁多不漏）
