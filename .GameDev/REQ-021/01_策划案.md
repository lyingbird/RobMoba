## 第一章 功能概述

### 1.1 设计目标

修复移动端摇杆输入状态与游戏阶段完全相反的问题：建立清晰的输入状态管理机制，确保摇杆在正确的游戏阶段启用或禁用，并建立 UI 交互优先级规则。

### 1.2 用户故事

**作为**手机端玩家，**我希望**在英雄选择界面打开时摇杆不会控制角色移动，而在确认英雄后可以正常使用摇杆移动角色，**这样**我在选择英雄时不会误触移动，在战斗中能流畅操控。

## 第二章 功能详细设计

### 2.1 根因分析

当前的摇杆输入存在两个反向 Bug：

**Bug A — 英雄选择界面时摇杆可用（不应该）**：
- 摇杆在大厅阶段初始化时就绑定了移动回调，并设置为 `enabled = true`
- 英雄选择界面是独立的全屏覆盖层，但触摸事件仍能穿透到下层摇杆触摸区域
- 缺乏"全屏菜单打开时禁用摇杆"的机制

**Bug B — 确认英雄后摇杆失效（应该工作）**：
- 确认英雄后，输入管理器初始化时重新绑定了摇杆方向回调
- 但输入管理器的启用状态默认为"未启用"
- 输入管理器只在"对决开始"事件时才被启用，而大厅/训练场自由活动模式下没有"对决开始"事件
- 原来的大厅直接回调被覆盖后，新回调因为启用状态为 false 而不响应

### 2.2 输入状态模型

定义三种输入状态：

| 输入状态 | 摇杆 | 技能按钮 | 说明 |
|---------|------|---------|------|
| **DISABLED** | 禁用，不响应触摸 | 禁用 | 全屏菜单打开时 |
| **LOBBY** | 启用，驱动角色移动 | 锁定（显示占位图标） | 未选英雄/大厅自由活动 |
| **COMBAT** | 启用，驱动角色移动 | 启用（显示技能图标） | 确认英雄后的战斗/训练状态 |

### 2.3 游戏阶段与输入状态映射

| 游戏阶段 | 对应输入状态 | 摇杆行为 | 触发条件 |
|---------|-------------|---------|---------|
| 进入大厅（初始） | LOBBY | 可移动角色 | 客户端启动完成 |
| 英雄选择界面打开 | DISABLED | 不响应触摸 | 全屏英雄选择面板 Show |
| 英雄选择界面关闭（未确认） | LOBBY | 恢复移动 | 关闭面板但未确认英雄 |
| 英雄确认 | COMBAT | 可移动+可释放技能 | 确认英雄回调 |
| 英雄切换面板打开 | DISABLED | 不响应触摸 | 重新打开英雄选择面板 |
| 英雄切换面板关闭 | COMBAT | 恢复移动+技能 | 关闭面板（已有确认英雄） |
| 对决开始 | COMBAT | 保持启用 | 对决事件 start |
| 对决结束 | COMBAT | 保持启用（回到训练场） | 对决事件 result |
| 角色死亡 | DISABLED | 禁用 | Humanoid.Died |
| 角色复活 | COMBAT | 恢复 | CharacterAdded |

### 2.4 UI 交互优先级规则

**核心原则：全屏/半屏菜单交互优先级高于移动操控**

优先级层次（从高到低）：
1. **系统菜单**（Roblox 内置暂停菜单等）
2. **全屏游戏菜单**（英雄选择面板、设置面板等）
3. **操控输入**（摇杆移动、技能释放）
4. **背景信息**（小地图、HUD数据展示）

**规则**：
- 当高优先级 UI 元素激活时，自动禁用低优先级的输入响应
- 当高优先级 UI 元素关闭时，自动恢复低优先级的输入响应
- 禁用/恢复应在同一帧内生效，无延迟

### 2.5 状态切换时序

**初始化时序**（首次进入）：
```
客户端启动 → 摇杆Init → 设为LOBBY状态（可移动）
→ 英雄选择Show → 设为DISABLED状态
→ 用户确认英雄 → 英雄选择Hide → 设为COMBAT状态
→ 输入管理器Init（自动启用）→ 绑定摇杆+技能回调
```

**英雄切换时序**：
```
点击切换英雄按钮 → 英雄选择Show → 设为DISABLED状态
→ 用户确认新英雄 → 英雄选择Hide → 设为COMBAT状态
→ 更新技能按钮
```

**菜单开关通用时序**：
```
菜单打开 → 保存当前输入状态 → 设为DISABLED
→ 菜单关闭 → 恢复保存的输入状态
```

## 第三章 验收标准

### 3.1 正常流程

- [ ] **AC-001**: 移动端进入大厅后、英雄选择界面打开前，摇杆触摸可以控制角色移动
- [ ] **AC-002**: 移动端英雄选择全屏面板打开时，摇杆触摸不应驱动角色移动（输入被禁用）
- [ ] **AC-003**: 移动端确认英雄后，英雄选择面板关闭，摇杆触摸可以控制角色移动
- [ ] **AC-004**: 移动端确认英雄后，技能按钮从锁定态变为可用态，可以正常释放技能
- [ ] **AC-005**: 移动端点击"切换英雄"重新打开选择面板时，摇杆输入被禁用；关闭后恢复

### 3.2 边界条件

- [ ] **AC-006**: 在英雄选择面板打开期间，即使手指在摇杆触摸区域拖动，角色也不应移动
- [ ] **AC-007**: 快速连续打开/关闭英雄选择面板（2次以内间隔<0.5秒），摇杆状态应正确恢复
- [ ] **AC-008**: PC端（isMobile=false）不受本次改动影响，PC端输入系统行为不变

### 3.3 异常情况

- [ ] **AC-009**: 如果英雄选择面板异常关闭（被其他代码Destroy），摇杆应恢复为可用状态而非永久禁用
- [ ] **AC-010**: 对决开始/结束事件与输入状态切换不冲突（对决结束后回到训练场，摇杆仍可用）
