# REQ-019: MCP 测试 GM 命令

## 基本信息

| 属性 | 值 |
|------|-----|
| 需求类型 | CONFIG |
| 需求规模 | XS（极小） |
| 优先级 | P1（测试效率） |
| 流程模式 | 标准模式 |
| 复杂度 | 简单 |
| 关联需求 | REQ-018（Device Emulator测试中发现MCP无法点击GUI按钮） |

## 需求描述

在 `Client.client.lua` 中注册 `_G.GM_ForceHeroConfirm(heroId)` 全局GM命令，使 MCP 的 `execute_luau` 可以直接跳过英雄选择界面进入战斗场景。

### 背景

REQ-018 测试过程中发现 MCP 工具的三个关键限制：
1. `user_mouse_input("click")` 无法触发 Roblox GUI 的 `MouseButton1Click` 信号
2. `user_keyboard_input` 的 `MouseLeftButton` 也无法触发 GUI 按钮回调
3. MCP 无法模拟鼠标拖拽（mouseDown→drag→mouseUp）

这导致每次 MCP 自动化测试都需要复杂的 `execute_luau` 脚本来模拟整个 `onHeroConfirmed` 逻辑链（10+ 步骤），极其脆弱且不可维护。

### 解决方案

注册一个 GM 命令，通过 `BindableFunction` 桥梁跨上下文调用。MCP 测试时只需：
```lua
local bf = game.Players:GetPlayers()[1].PlayerScripts.Modules:FindFirstChild("GM_ForceHeroConfirm")
bf:Invoke("LianPo")  -- 或 bf:Invoke() 默认使用 LianPo
```

即可完成英雄选择并进入战斗场景，等效于用户在 UI 上选择英雄并点击确认。

**技术说明**: `execute_luau` 运行在 CoreGui 上下文（插件侧），与客户端 LocalScript 的 `_G` 和 `require` 缓存隔离。使用 `BindableFunction` 挂载在 `PlayerScripts` 下作为跨上下文调用桥梁。

## 验收标准

| AC | 描述 | 验证方式 |
|----|------|----------|
| AC-001 | `GM_ForceHeroConfirm` BindableFunction 存在 | execute_luau: `PlayerScripts:FindFirstChild("GM_ForceHeroConfirm")` |
| AC-002 | 调用后英雄选择界面消失 | execute_luau: `PlayerGui:FindFirstChild("HeroSelectScreen") == nil` |
| AC-003 | 调用后进入战斗场景（摇杆可操作、技能按钮显示） | execute_luau: 验证系统初始化状态 |
| AC-004 | 默认参数（无参调用）使用 "LianPo" | execute_luau: `bf:Invoke()` 成功 |
