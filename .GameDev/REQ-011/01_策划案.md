# 第一章 功能概述

将 RobMoba 项目的 UI 和操控系统从 PC 端键鼠操作**全面改造**为手机端 MOBA 标准触屏操作，参考王者荣耀手机端 UI 布局和交互范式。

## 1.1 设计目标

| 目标 | 描述 | 优先级 |
|------|------|--------|
| 触屏核心操控 | 虚拟摇杆移动 + 技能按钮方向轮盘释放，替代键鼠操作 | P0 |
| 手机MOBA标准布局 | 左摇杆 + 右技能 + 顶部HUD + 小地图，对标王者荣耀 | P0 |
| 服务端零改动 | 仅改造客户端，复用现有 RemoteEvent 协议和服务端逻辑 | P0 |
| 多点触控 | 左手移动 + 右手技能同时操作，互不干扰 | P0 |
| 辅助UI适配 | 英雄选择/背包/匹配等辅助界面触屏可用 | P2 |

## 1.2 用户故事

作为一个 **手机端 Roblox 玩家**，
我想要 **用虚拟摇杆控制移动、用触屏按钮释放技能（按住拖拽选方向、松手释放）**，
以便 **在手机上获得和王者荣耀相似的流畅MOBA操控体验**。

## 1.3 参考素材

- 王者荣耀兰陵王实战截图（展示：左摇杆 + 右侧技能按钮 + 顶部HUD + 小地图）
- 王者荣耀赵云实战截图（展示：技能按钮弧形布局 + 普攻按钮 + 召唤师技能 + 装备主动）

**王者荣耀标准布局总结**：
- **左下**：虚拟摇杆（移动）
- **右下**：技能按钮弧形排列（Q/W/R）+ 大号普攻按钮 + 召唤师技能（D/F）
- **左上**：小地图 + 英雄头像/HP/MP
- **顶部居中**：对局时间 + 比分
- **底部中央**：装备栏/物品主动

### 当前输入系统（需替换）

| 项目 | 当前实现 | 目标实现 |
|------|---------|---------|
| 操控风格 | LOL 风格（右键移动 + 技能键释放） | 王者荣耀风格（虚拟摇杆 + 触屏按钮） |
| 移动方式 | 鼠标右键点击/长按移动(Pathfinding) | 左侧虚拟摇杆持续方向移动 |
| 技能释放 | Q/W/E/R 键 + 鼠标指向 | 触屏技能按钮 + 方向轮盘拖拽 |
| 普攻 | 鼠标点击目标 / A键 | 右下角大号普攻按钮（自动索敌） |

### 服务端接口（保持稳定）

以下 RemoteEvent 的**服务端逻辑不变**，仅客户端发送方式改变：

| 事件名 | 方向 | 影响 |
|--------|------|------|
| CastSkillEvent | C→S | 触发源从键盘按键改为触屏按钮 |
| SkillDirectionEvent | C→S | 方向数据从鼠标位置改为摇杆/轮盘方向 |
| AttackTargetEvent | C→S | 触发源从鼠标点击改为普攻按钮 |

> 💡 [假设] 现有16个RemoteEvent中，仅上述3个C→S事件的客户端触发逻辑需要修改，其余事件（S→C同步类、双向匹配类）完全不受影响。

## 2.2 MOD-01 虚拟摇杆系统

### 核心机制

| 子系统 | 说明 |
|--------|------|
| **外圈+摇杆球** | 固定半径外圈（半透明圆环）+ 跟随手指的摇杆球（实心圆） |
| **动态出现模式** | 手指按下时在触摸点位置显示摇杆，松开后0.3s淡出隐藏 |
| **方向映射** | 摇杆偏移向量归一化 → 角色在世界坐标系的移动方向（需考虑摄像机朝向投影） |
| **速度映射** | 偏移距离/最大半径 = 速度百分比。0~40%=慢走(50%速), 40~100%=全速跑 |
| **死区设计** | 中心15%半径内不触发移动，防止误触 |
| **触摸区域** | 屏幕左半区域(0~50% X)任意位置可激活摇杆 |

### 交互流程

```
玩家手指按下(左半屏)
  → 判断是否在左半区域(X < 50%屏宽)
    → 是: 在触摸点位置实例化摇杆UI(外圈+摇杆球)
    → 否: 忽略(交给右侧技能系统)
  → 手指移动:
    → 计算手指相对摇杆中心的偏移向量
    → 若偏移 > 最大半径: 钳位到最大半径(摇杆球不超出外圈)
    → 若偏移 < 死区半径(15%): 不触发移动
    → 否则: 归一化方向 → 发送移动方向给 InputAdapter
  → 手指抬起:
    → 停止移动
    → 摇杆UI 0.3s 淡出消失
```

### 界面需求

```
┌─────────────────────────────────────────────┐
│                                             │
│  [小地图]                    [顶部信息栏]    │
│  [头像HP/MP]                                │
│                                             │
│                                             │
│                                             │
│                                      [W]    │
│        ┌───┐                      [Q] [R]   │
│        │ ○ │ ← 摇杆              [D][F]     │
│        └───┘                     [普攻]      │
│  ← 左半屏触摸区 →      ← 右半屏技能区 →     │
└─────────────────────────────────────────────┘
```

- 摇杆外圈直径: 约屏幕高度的 25%
- 摇杆球直径: 外圈的 40%
- 外圈颜色: 白色, 透明度 0.4
- 摇杆球颜色: 白色, 透明度 0.8

## 2.3 MOD-02 技能按钮与方向轮盘

### 核心机制

#### 按钮布局（王者荣耀标准弧形）

```
         [W]
      [Q]   [R]      ← 技能按钮弧形排列
    [D] [F]           ← 召唤师技能
         [普攻]       ← 最大按钮，最底部
```

| 按钮 | 大小(屏幕高度比) | 位置描述 |
|------|-----------------|---------|
| 普攻 | 14% | 右下角，距底部 8%，距右侧 6% |
| R（大招） | 11% | 普攻按钮左上方，弧形45°位置 |
| W | 11% | R按钮正上方 |
| Q | 11% | W按钮左侧 |
| D（召唤师1） | 8% | Q按钮左下方 |
| F（召唤师2） | 8% | D按钮下方 |

> 💡 [假设] 按钮具体像素位置在实现时通过 UDim2 Scale 定位，上述比例为设计稿基准，程序可在 ±10% 范围内微调。

#### 方向轮盘瞄准（指向性技能）

```
玩家按住技能按钮(如Q)
  → 进入AIMING状态
  → 以按钮中心为原点，显示方向指示器(扇形/线条)
  → 同时在角色脚下显示技能范围预览(来自SkillConfig.range)
  → 手指拖拽:
    → 计算手指相对按钮中心的角度
    → 旋转方向指示器到该角度
    → 更新角色脚下范围预览的朝向
  → 手指松开:
    → 判断手指是否在"取消区"(距按钮中心 < 按钮半径的30%)
      → 是: 取消释放，回到IDLE
      → 否: 将方向角度转为世界坐标方向 → SkillDirectionEvent → CastSkillEvent
  → 方向指示器消失
```

#### 技能类型与交互方式映射

| 技能类型(SkillConfig.aimType) | 交互方式 | 示例 |
|------|---------|------|
| `directional` (指向性) | 按住→拖拽方向→松手释放 | 拉克丝Q(光之束缚), 后羿R |
| `area` (范围) | 按住→拖拽方向→松手释放(显示圆形范围) | 拉克丝E(光芒奇点) |
| `self` (自身) | 点按即释放 | 拉克丝W(曲光屏障), 廉颇W(护盾) |
| `channel` (引导) | 点按开始引导 | 安琪拉R(炽热光辉引导) |
| `none` (无目标) | 点按即释放 | — |

> 💡 [假设] SkillConfig 中需新增 `aimType` 字段来标识技能瞄准类型。若现有 Config 无此字段，默认所有技能为 `directional`（带方向轮盘），程序实现时根据已有技能特征自动映射。

#### CD 显示

- 技能CD中: 按钮上覆盖**顺时针旋转的灰色扇形遮罩**
- 遮罩中央显示剩余秒数（白色粗体数字，1位小数 如 "3.2"）
- CD结束时: 遮罩消失 + 短暂亮光闪烁提示

#### 不可用状态

| 状态 | 表现 |
|------|------|
| CD中 | 灰色扇形遮罩 + 秒数 |
| MP不足 | 按钮整体变暗(Transparency=0.6) + 蓝色边框闪烁 |
| 沉默/眩晕 | 按钮变暗 + 锁链图标覆盖 |
| 死亡 | 所有按钮变暗不可交互 |
| 未学习 | 按钮显示锁定图标（当前Q/W/R全部开放，暂不涉及） |

## 2.4 MOD-03 战斗HUD重构

### 核心机制

```

```

#### 顶部信息栏

| 元素 | 位置 | 规格 |
|------|------|------|

| HP条 | 头像右侧 | 宽=屏宽15%, 高=屏高2%, 绿色→黄色→红色渐变 |

| 击杀比分 | 计时器两侧 | "红方杀数 vs 蓝方杀数" |

- 位置: 屏幕上方 20% 区域居中
- 格式: "[击杀者头像] 击杀了 [被杀者头像]"
- 动画: 从上方滑入 → 停留 2s → 向上淡出
- 堆叠: 最多同时显示 2 条，新通知顶掉旧通知

#### 复活倒计时

- 死亡时屏幕中央显示大号灰色倒计时数字
- 背景半透明黑色遮罩(Transparency=0.5)
- 倒计时结束后遮罩淡出

## 2.5 MOD-04 输入系统适配层

### 核心机制

#### 架构设计

```
[MOD-01 虚拟摇杆]  ──→ moveDirection: Vector2
                         ↓
[MOD-04 InputAdapter] ──→ 转换为世界坐标方向 ──→ MovementManager.setMoveDirection(dir)
                         ↑
[MOD-02 技能按钮]  ──→ skillId + aimDirection: Vector2
                         ↓
[MOD-04 InputAdapter] ──→ SkillDirectionEvent:FireServer(dir)
                         ──→ CastSkillEvent:FireServer(skillId)
                         ↑
[MOD-02 普攻按钮]  ──→ attackPressed
                         ↓
[MOD-04 InputAdapter] ──→ getNearestEnemy() ──→ AttackTargetEvent:FireServer(target)
```

#### 移动管线改造

| 对比项 | 旧(键鼠) | 新(触屏) |
|--------|---------|---------|
| 输入源 | 右键点击位置 | 摇杆方向向量(持续) |
| 移动方式 | Pathfinding 寻路到目标点 | 直接方向移动(HumanoidMoveDirection) |
| 停止条件 | 到达目标点 | 松开摇杆 |
| 每帧更新 | 否(一次性目标) | 是(每帧读取摇杆方向) |

> 💡 [假设] 现有 MovementManager 的 Pathfinding 逻辑将被替换为直接方向移动（`Humanoid:Move(direction)`），Pathfinding 模块代码保留但不再被触屏输入调用。

#### 技能释放管线改造

## 2.6 MOD-05 摄像机系统适配

### 核心机制

| 参数 | 值 | 说明 |
|------|-----|------|
| 俯视角度 | 50° | 从水平面计算的俯视角(王者荣耀标准约45°~55°) |
| 跟随距离 | 40 studs | 摄像机到角色的3D距离 |

| 水平偏移 | ~25.7 studs | distance × cos(50°) |
| 平滑系数 | 0.15 | Lerp 插值系数(每帧), 越大越紧跟 |
| 朝向 | 固定北方(0,0,-1) | 摄像机始终朝-Z方向看，不随角色旋转 |

> 💡 [假设] 当前摄像机可能已有某种跟随逻辑，此模块将完全接管 `Camera.CameraType = Enum.CameraType.Scriptable`，禁用默认Roblox摄像机控制。

### 交互流程

```
每帧(RenderStepped):
  → 获取角色 HumanoidRootPart 位置
  → 计算目标摄像机位置 = 角色位置 + Vector3.new(0, height, offset)
  → Camera.CFrame = Camera.CFrame:Lerp(targetCFrame, smoothFactor)

技能特写触发(SkillCameraEvent):
  → 暂停跟随逻辑
  → 执行特写/震动
  → 特写结束 → 恢复跟随逻辑(平滑过渡回来)
```

## 2.9 全局交互流程

### 完整对局触屏操作流程

```
[大厅阶段]
  玩家进入大厅 → 触屏点击英雄面板选择英雄 → 触屏操作训练场面板
  → 走到匹配区域 → 点击匹配按钮 → 匹配等待

[对决阶段]
  3秒倒计时 → 对局开始
  → 左手摇杆移动 + 右手技能释放(同时操作)
  → 循环:
    1. 推摇杆 → 英雄朝摇杆方向持续移动
    2. 看到敌人 → 按住Q技能 → 拖拽选方向 → 松手释放Q
    3. 敌人靠近 → 点击普攻 → 自动锁定攻击
    4. 技能CD中 → 观察CD倒计时 → CD好了再释放
    5. HP低 → 使用召唤师技能恢复/闪现
    6. 被击杀 → 观察复活倒计时 → 复活继续

[结算阶段]
  3杀获胜 → 5秒结算展示 → 自动返回大厅
```

| 2 | 摇杆区域 | 移动持续进行 |
| 3 | HUD交互元素 | 装备栏、小地图点击 |
| 4(最低) | 空白区域 | 忽略 |

## 2.10 边界条件与异常处理

| 场景 | 预期行为 |
|------|---------|
| 同时按下两个技能按钮 | 先按下的优先，后按下的忽略（AIMING 状态下锁定当前技能） |
| 摇杆拖拽中手指滑出屏幕 | 等同于松手，立即停止移动 |
| 技能CD中按下按钮 | 无响应，按钮视觉反馈(短暂闪红) |
| MP不足时按下技能 | 无响应，MP条闪烁提示 |
| 死亡状态操作任何按钮 | 全部忽略，仅显示复活倒计时 |
| 角色被控制(眩晕/击飞)时操作摇杆 | 摇杆可拖动但不产生移动，控制结束后立即响应当前摇杆方向 |
| 角色被控制时按技能 | 忽略技能输入，按钮显示锁链状态 |
| 方向轮盘拖拽距离极小(<5px) | 视为取消操作，不释放技能 |
| 技能释放瞬间被眩晕 | 遵循现有服务端逻辑(CanCast检查)，客户端恢复IDLE |
| 网络延迟导致CD不同步 | 以服务端 SyncCooldownEvent 为准，客户端CD可能短暂跳变 |
| 设备性能过低导致帧率低 | 摇杆/按钮输入不依赖帧率，使用 InputChanged 事件而非每帧轮询 |
| 设备旋转(竖屏) | 强制横屏锁定（Roblox 默认设置） |

# 第四章 风险与依赖

## 4.1 优先级与排期

- **优先级**: P0（核心体验改造）
- **预估工作量**: 810 分钟（~13.5 小时，XL规模）
- **实施阶段**: Phase A(P0) → Phase B(P1) → Phase C(P2)

## 4.2 风险

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 多点触控在低端设备上不稳定 | 高 | 使用 GuiButton 的 InputBegan/InputChanged 而非全局 UserInputService，每个触摸点独立追踪 |

| 摇杆方向→世界坐标转换精度 | 中 | 使用 Camera:ViewportPointToRay 转换，考虑摄像机旋转 |
| 方向轮盘取消区手感不好 | 中 | 取消区阈值设为可配置参数，上线后根据反馈调整 |
| 现有 Pathfinding 移动与摇杆直接移动行为差异 | 中 | 新增移动模式枚举(PATHFIND/DIRECT)，摇杆模式使用 Humanoid:Move |
| 技能范围预览在触屏上遮挡视野 | 低 | 预览使用高透明度(0.7)，不阻挡触摸事件(Interactable=false) |
