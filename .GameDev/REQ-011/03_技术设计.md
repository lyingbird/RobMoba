## 1. 策划案评审

| 项目 | 结果 |
|------|------|
| 策划案版本 | v1.0 |
| UX设计版本 | v1.0 (已确认) |
| 技术可行性 | ✅ 可行 |
| 服务端影响 | ⚪ 零改动（3个C→S RemoteEvent仅客户端触发源变更） |
| 评审总结 | 纯客户端改造，架构可行。关键挑战在多点触控冲突处理和摇杆→世界坐标转换精度 |

### 1.1 可行性逐项评估

| 策划需求 | 技术评估 | 风险等级 |
|----------|---------|---------|
| 虚拟摇杆移动 | ✅ Roblox `UserInputService.TouchMoved` + `Humanoid:Move(direction)` 原生支持 | 低 |
| 技能方向轮盘 | ✅ `GuiObject.InputBegan/InputChanged` 可追踪独立触摸点 | 中（多指冲突） |
| 多点触控 | ✅ Roblox 支持多触摸点追踪（每个 InputObject 有唯一 ID） | 中 |
| CD扇形遮罩 | ✅ `ImageLabel.ImageRectOffset` + `Rotation` 模拟扇形消退 | 低 |
| 自动索敌 | ✅ 复用现有 `CombatUtils.getEnemiesInRange()` | 低 |
| 摇杆→世界坐标 | ⚠️ 需考虑固定摄像机角度下2D→3D投影。摄像机朝-Z固定，摇杆X/Y直接映射世界X/Z | 中 |
| 摄像机Lerp平滑 | ✅ 改 `CFrame:Lerp(target, factor)` 替代当前直接赋值 | 低 |
| 方向轮盘取消区 | ✅ 距离计算判断是否在取消半径内 | 低 |
| 服务端零改动 | ✅ 已验证：CastSkillEvent/SkillDirectionEvent/AttackTargetEvent 参数格式不变 | 无 |

### 1.2 对策划案的技术建议

| # | 建议 | 原因 | 影响 |
|---|------|------|------|
| 1 | `SkillConfig` 新增 `aimType` 字段 | 区分指向/自身/引导技能的交互方式 | 需修改 Config 表，默认 `"directional"` |
| 2 | 移动模式采用 `Humanoid:Move(direction)` 而非 `Humanoid:MoveTo(position)` | 摇杆为持续方向输入，非目标点输入 | MovementManager 需新增 API |
| 3 | 小地图采用纯 UI 方案（非 ViewportFrame） | ViewportFrame 性能开销大，1v1 场景用坐标映射即可 | 开发更简单，性能更好 |
| 4 | 保留 PC InputManager 代码但不激活 | 未来可能需要 PC/Mobile 双端支持 | 条件分支切换而非删除 |

## 3. 系统架构

### 3.1 架构概览

```
┌────────────────────────────────────────────────────────────────────┐
│                        表现层 (UI Layer)                            │
│                                                                    │
│  UI_VirtualJoystick    UI_SkillButtons    UI_MobileHUD             │
│  (MOD-01)              (MOD-02)           (MOD-03)                 │
│                        └─ DirectionWheel                           │
│  UI_Minimap            UI_MobileAuxiliary                          │
│  (MOD-06)              (MOD-06)                                    │
└────────┬───────────────────┬──────────────────────────────────────┘
         │ 触摸事件回调       │ 触摸事件回调
         ▼                   ▼
┌────────────────────────────────────────────────────────────────────┐
│                     适配层 (Adapter Layer)                          │
│                                                                    │
│  MobileInputManager (MOD-04)                                       │
│  ├─ 接收摇杆方向 → 驱动 MovementManager                             │
│  ├─ 接收技能+方向 → 驱动 CastSkillEvent/SkillDirectionEvent         │
│  ├─ 接收普攻请求 → getNearestEnemy → AttackTargetEvent              │
│  └─ 状态机: IDLE/AIMING/CASTING/ATTACK_AIMING (复用现有状态定义)     │
└────────┬───────────────────────────────────────────────────────────┘
         │ 调用现有API
         ▼
┌────────────────────────────────────────────────────────────────────┐
│                     基础层 (Existing Systems)                       │
│                                                                    │
│  MovementManager ← 扩展: SetMoveDirection(dir)                     │
│  CameraManager   ← 扩展: Lerp平滑 + 移动端参数                     │
│  CooldownManager (不变)                                             │
│  HeroAnimator    (不变)                                             │
│  CinematicManager(不变)                                             │
│  UIManager       (不变)                                             │
└────────────────────────────────────────────────────────────────────┘
         │ RemoteEvent (参数格式不变)
         ▼
┌────────────────────────────────────────────────────────────────────┐
│                     服务端 (零改动)                                  │
│  PlayerSkillManager / AutoAttackManager / MatchSystem / etc.       │
└────────────────────────────────────────────────────────────────────┘
```

**设计决策**: 三层分离 — UI层只处理触摸交互和视觉表现，适配层负责触摸数据→游戏逻辑转换，基础层复用现有系统。

### 3.2 核心模块设计

#### MOD-01: UI_VirtualJoystick (虚拟摇杆)

```
职责: 左半屏触摸检测 → 摇杆UI显示/跟随 → 输出方向向量
无状态依赖, 纯UI模块

类结构:
  UI_VirtualJoystick (ModuleScript)
  ├─ 常量: MAX_RADIUS, DEADZONE_PERCENT, FADE_TIME, WALK_THRESHOLD
  ├─ Init(parentFrame) → 创建UI元素, 绑定触摸事件
  ├─ _onTouchBegan(input) → 在触摸点显示摇杆
  ├─ _onTouchMoved(input) → 计算偏移, 钳位, 输出方向
  ├─ _onTouchEnded(input) → 淡出摇杆, 通知方向归零
  ├─ GetDirection() → Vector2 (当前方向, 归一化)
  ├─ GetMagnitude() → number (0~1, 速度百分比)
  ├─ SetEnabled(enabled) → 死亡/被控时禁用
  └─ Destroy() → 清理
  
  回调: OnDirectionChanged(direction: Vector2, magnitude: number)
```

#### MOD-02: UI_SkillButtons + DirectionWheel (技能按钮+方向轮盘)

```
职责: 技能按钮交互 → 方向轮盘瞄准 → 输出技能ID+方向
依赖: CooldownManager(CD数据), SkillRegistry(技能配置)

类结构:
  UI_SkillButtons (ModuleScript)
  ├─ 常量: BTN_SIZE_NORMAL/ATTACK/SUMM, AIM_CANCEL_THRESHOLD
  ├─ Init(parentFrame, skillSlots) → 创建6个按钮(Q/W/R/D/F/普攻)
  ├─ _createSkillButton(slotKey, config) → 单个按钮UI
  ├─ _onButtonTouchBegan(slotKey, input) → 判断技能可用性
  ├─ _onButtonTouchMoved(slotKey, input) → 更新方向轮盘
  ├─ _onButtonTouchEnded(slotKey, input) → 释放或取消
  ├─ _showDirectionWheel(button, skillConfig) → 显示方向指示器
  ├─ _hideDirectionWheel() → 隐藏
  ├─ _updateCooldownDisplay(slotKey, remaining, total) → CD扇形遮罩
  ├─ SetSkillState(slotKey, state) → 8种状态切换
  ├─ SetEnabled(enabled) → 全局启用/禁用
  ├─ UpdateAttackButton(hasTarget) → 普攻按钮状态
  └─ Destroy()
  
  回调: OnSkillCast(skillId: number, direction: Vector3?)
  回调: OnAttackPressed()
```

```
职责: 顶部信息栏(HP/MP/等级/计时/比分) + 击杀播报 + 复活倒计时
依赖: Attribute桥(HP/MP同步), DuelEvent(对决状态), MatchSystem(击杀通知)

类结构:
  UI_MobileHUD (ModuleScript)
  ├─ Init(parentFrame) → 创建HUD框架
  ├─ _createTopBar() → 头像+HP条+MP条+等级+计时+比分
  ├─ _createKillFeed() → 击杀播报区域
  ├─ _createRespawnOverlay() → 复活倒计时遮罩
  ├─ UpdateHP(current, max) → HP条动画
  ├─ UpdateMP(current, max) → MP/能量条动画
  ├─ UpdateLevel(level) → 等级数字
  ├─ UpdateTimer(timeSeconds) → 计时器更新
  ├─ UpdateScore(redKills, blueKills) → 比分
  ├─ ShowKillNotification(killer, victim) → 击杀播报
  ├─ ShowRespawnCountdown(seconds) → 复活倒计时
  ├─ HideRespawnCountdown() → 隐藏
  ├─ SetVisible(visible) → 对决中显示/大厅隐藏
  └─ Destroy()
```

#### MOD-04: MobileInputManager (输入系统适配层)

```
职责: 汇总摇杆/技能/普攻输入 → 驱动移动/技能释放/普攻
依赖: MovementManager, CooldownManager, SkillRegistry, CombatUtils(客户端索敌)
核心: 替代现有 InputManager.lua 在移动端的角色

类结构:
  MobileInputManager (ModuleScript)
  ├─ 常量: AUTO_ATTACK_RANGE, NEAREST_ENEMY_SEARCH_RADIUS
  ├─ Init(character, modules) → 初始化, 关联UI_VirtualJoystick和UI_SkillButtons
  ├─ _onJoystickDirection(direction, magnitude) → 摇杆方向→世界方向→移动
  ├─ _screenToWorldDirection(screenDir) → 2D摇杆方向→3D世界方向(考虑摄像机角度)
  ├─ _onSkillCast(skillId, direction) → 技能释放管线
  ├─ _onAttackPressed() → 普攻管线(自动索敌)
  ├─ _getNearestEnemy() → Model? (射程内最近敌人)
  ├─ SetEnabled(enabled) → 启用/禁用全部输入
  ├─ GetState() → 当前状态(IDLE/AIMING/CASTING)
  └─ Destroy()
  
  状态机: IDLE → AIMING(按住技能) → CASTING(松手释放) → IDLE
          IDLE → ATTACK_AIMING(按普攻) → IDLE
```

### 3.3 关键流程

#### 3.3.1 移动流程 (摇杆→角色移动)

```
触摸左半屏 (InputBegan)
  → UI_VirtualJoystick._onTouchBegan()
  → 显示摇杆UI在触摸点
  
手指拖动 (InputChanged)
  → UI_VirtualJoystick._onTouchMoved()
  → 计算偏移向量, 钳位到MAX_RADIUS
  → 判断死区(< DEADZONE_PERCENT * MAX_RADIUS → 忽略)
  → 归一化方向, 计算速度比例
  → 触发回调 OnDirectionChanged(dir, magnitude)
  
MobileInputManager._onJoystickDirection(dir, magnitude)
  → _screenToWorldDirection(dir) → worldDir: Vector3
  → 速度判断: magnitude < WALK_THRESHOLD → 50%速, 否则 100%速
  → MovementManager.SetMoveDirection(worldDir * speed)
  
MovementManager (每帧 RenderStepped):
  → if moveDirection ~= Vector3.zero then
  →   Humanoid:Move(moveDirection)
  → else
  →   Humanoid:Move(Vector3.zero) -- 停止

手指抬起 (InputEnded)
  → UI_VirtualJoystick._onTouchEnded()
  → 淡出摇杆(TweenService, 0.3s)
  → 触发 OnDirectionChanged(Vector2.zero, 0)
  → MovementManager.SetMoveDirection(Vector3.zero) -- 停止移动
```

#### 3.3.2 技能释放流程 (方向轮盘→技能释放)

```
按住技能按钮 (InputBegan on GuiButton)
  → UI_SkillButtons._onButtonTouchBegan(slotKey, input)
  → 检查: CD? → 闪红返回 | MP不足? → 闪蓝返回 | 被控? → 忽略返回
  → 查询 SkillConfig.aimType:
    → "self"/"channel"/"none" → 直接触发 OnSkillCast(skillId, nil)
    → "directional"/"area" → 进入AIMING状态
  → _showDirectionWheel(button, skillConfig)
  → MobileInputManager 状态 → AIMING

手指拖动 (InputChanged)
  → UI_SkillButtons._onButtonTouchMoved()
  → 计算手指相对按钮中心的偏移
  → 偏移距离 < cancelThreshold → 显示取消标记(✕)
  → 偏移距离 >= cancelThreshold → 旋转方向指示线
  → (可选) 更新角色脚下技能范围预览

手指松开 (InputEnded)
  → UI_SkillButtons._onButtonTouchEnded()
  → 最终偏移 < cancelThreshold → 取消, 隐藏轮盘, 回IDLE
  → 最终偏移 >= cancelThreshold:
    → 计算方向角度 → 转为世界坐标方向
    → 触发 OnSkillCast(skillId, worldDirection)
    
MobileInputManager._onSkillCast(skillId, direction)
  → if direction then
  →   SkillDirectionEvent:FireServer(direction)
  → CastSkillEvent:FireServer(skillId, direction or Vector3.zero)
  → 状态 → IDLE
```

#### 3.3.3 普攻流程

```
点击普攻按钮 (Activated on GuiButton)
  → UI_SkillButtons.OnAttackPressed()
  
MobileInputManager._onAttackPressed()
  → target = _getNearestEnemy()
  → if target == nil → 反馈"无目标", return
  → AttackTargetEvent:FireServer(target)
  → (视觉反馈: 按钮闪光)
```

## 6. 技术风险

| # | 风险 | 影响 | 概率 | 应对措施 |
|---|------|------|------|----------|
| 1 | **多点触控冲突**: 左手摇杆和右手技能的TouchId管理不当 | 高 | 中 | 每个UI元素绑定独立InputObject追踪, 使用GuiObject.InputBegan而非全局UserInputService |
| 2 | **摇杆→世界坐标精度**: 2D屏幕方向映射到3D世界方向存在偏差 | 中 | 低 | 固定摄像机角度(不旋转)简化为X/Y直接映射X/Z, 单元测试验证8方向正确性 |
| 3 | **CD扇形遮罩性能**: 每帧更新多个扇形遮罩可能有开销 | 中 | 低 | 使用ImageRectOffset裁剪而非动态生成Mesh, 仅CD中的按钮更新 |
| 4 | **方向轮盘手感**: 取消区阈值不合适导致误操作 | 中 | 中 | 取消阈值设为MobileConfig可配置参数, 测试后调优 |
| 5 | **Humanoid:Move vs Humanoid:MoveTo 行为差异**: 摇杆直接移动不经过寻路, 可能穿过小障碍物 | 低 | 中 | 竞技场地形简单(平坦), Humanoid:Move自带碰撞检测, 实测观察 |
| 6 | **UI_MobileHUD 替代 UI_HUD 的功能遗漏**: 新HUD可能漏掉现有HUD的某些显示功能 | 中 | 低 | 逐项对照现有UI_HUD的功能列表, 确保战斗必要信息全部覆盖 |

### 关键集成点: Client.client.lua 改造

```lua
-- 现有代码(简化):
-- 英雄选择后 → InputManager.Init(character, ...)

-- 改造后:
local isMobile = UserInputService.TouchEnabled and not UserInputService.KeyboardEnabled

if isMobile then
    -- 移动端: 加载移动UI + MobileInputManager
    local UI_VirtualJoystick = require(UIComponents.UI_VirtualJoystick)
    local UI_SkillButtons = require(UIComponents.UI_SkillButtons)
    local UI_MobileHUD = require(UIComponents.UI_MobileHUD)
    local MobileInputManager = require(Modules.MobileInputManager)
    
    -- 初始化移动端UI和输入
    UI_VirtualJoystick.Init(leftFrame)
    UI_SkillButtons.Init(rightFrame, skillSlots)
    UI_MobileHUD.Init(hudFrame)
    MobileInputManager.Init(character, { ... })
    CameraManager.SetMobileMode(true)
    
    -- DuelEvent 绑定
    DuelEvent.OnClientEvent:Connect(function(data)
        if data.type == "start" then
            MobileInputManager.SetEnabled(true)
        elseif data.type == "result" then
            MobileInputManager.SetEnabled(false)
        end
    end)
else
    -- PC端: 保持现有逻辑不变
    InputManager.Init(character, ...)
end
```

> ⚠️ **安全检查**: 本改造不涉及任何服务端逻辑变更。客户端仅改变 UI 交互方式和 RemoteEvent 的触发源，服务端验证逻辑(CanCast/CD检查/伤害计算)完全不变。**服务端零信任原则不受影响**。

## 9. 性能考量

| 关注点 | 预期指标 | 优化策略 |
|--------|----------|----------|
| **RenderStepped 占用** | <1ms 新增开销 | 摇杆方向更新+移动驱动每帧执行, 但逻辑简单(向量计算) |
| **UI 元素数量** | 新增 ~30 个 GuiObject | 合理范围, 不会造成渲染瓶颈 |
| **CD 遮罩更新** | 最多同时 3 个按钮有CD | 仅CD中的按钮每帧更新 Rotation, 其余静态 |
| **小地图更新** | 每 0.5s 一次 | 非每帧, 开销可忽略 |
| **索敌搜索** | 每次普攻一次, 非每帧 | 1v1场景仅搜索1个敌人, O(1)复杂度 |
| **TweenService** | 动画使用 Tween | Roblox 原生 Tween 性能优秀, 无额外开销 |
| **触摸事件频率** | InputChanged 约 60fps | 回调内仅做向量计算, 无 Instance 创建 |

**性能预算**: 移动端新增系统总 RenderStepped 开销 < 2ms（60FPS 帧预算 16.7ms，占比 <12%）。

**内存预算**: 新增 ~30 个 GUI Instance + 6 个 ModuleScript，总内存增量 < 1MB。
