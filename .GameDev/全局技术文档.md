### 3.2 数据流

#### 技能释放流程
```
Client: InputManager 按下技能键
  → 计算方向/目标
  → CastSkillEvent:FireServer(skillId, direction)
  
Server: PlayerSkillManager:OnCastSkill(player, skillId, direction)
  → 验证冷却/蓝量/状态
  → SkillModuleMap[skillId] → Skill_XXXX:execute(caster, direction)
  → CombatUtils.getEnemiesInRange(caster, pos, radius)
  → BuffSystem:ApplyEffect(caster, target, effectId)
  → EffectExecutor:Execute(effectType, source, target, effectData)
  → StatsManager.SetStat(target, "HP", newHP)
  
Server → Client: SkillVFXEvent:FireAllClients(skillId, caster, position, direction)
Server → Client: SyncCooldownEvent:FireClient(player, skillId, cdTime)
```

#### 匹配对决流程
```
Client: 进入匹配区域 / MatchmakingEvent:FireServer({action="join"})

Server: LobbyManager
  → 验证英雄已选择 + 状态为 LOBBY
  → 加入 matchQueue
  → 队列 >= 2 → 匹配成功
  → 双方状态 → DUELING
  → MatchmakingEvent:FireClient (通知匹配状态)
  → DuelManager.CreateDuel(p1, p2)

Server: DuelManager
  → DuelEvent:FireClient ("matched") → 3s countdown → ("start")
  → 创建 Teams (RedTeam/BlueTeam)
  → 传送到竞技场
  → MatchSystem.StartBattle()
  → 每 0.5s 检测击杀
  → 达到 3 杀 → DuelEvent:FireClient ("result")
  → 5s 展示 → 传送回大厅 → 清理
```

## 五、关键系统详解

### 5.1 属性系统 (StatsManager)

**16 项属性**: MaxHP, HP, MaxMP, MP, ATK, AP, DEF, MR, MoveSpeed, AtkSpeed, CritRate, CritDmg, CDR, HpRegen, MpRegen, Penetration

**计算公式**:
```
最终属性 = Base + Growth × (Level-1) + EquipmentBonus
伤害公式 = ATK × (100 / (100 + DEF))    -- 物理
         = AP × (100 / (100 + MR))       -- 魔法
```

**Attribute 桥**: 所有属性通过 `Character:SetAttribute(key, value)` 同步到 Instance，客户端通过 `GetAttributeChangedSignal` 监听变化更新 UI。

**API**:
- `GetStat(character, statName)` / `SetStat(character, statName, value)`
- `GiveXP(player, amount)` — 自动升级 + 重算属性
- `EquipItem(player, slotKey, itemID)` / `UnequipItem(player, slotKey)`

### 5.2 Buff 系统 (BuffSystem)

**驱动方式**: `RunService.Heartbeat` 每帧 tick（非 task.delay）

**数据结构**: `activeBuffs[characterModel][instanceId] = BuffInstance`

**Heartbeat 每帧流程**:
1. 遍历所有活跃 Buff
2. DoT/HoT tick（检查 TickInterval）
3. Shield 破碎检查（ShieldAmount ≤ 0）
4. 到期检查（elapsed ≥ duration）
5. **批量移除**（不在遍历中直接删除 — toExpire 收集）
6. 清理无效/空角色条目

**叠加规则**: Replace / Stack(MaxStacks) / Refresh / Independent

**互斥组**: 同 MutexGroup 新效果施加时先移除所有同组旧效果

**API**:
- `ApplyEffect(source, target, effectId)` → instanceId
- `RemoveEffect(target, effectId)` / `RemoveAllEffects(target)`
- `HasEffect(target, effectId)` / `HasCCType(target, ccType)`
- `GetBuffStacks(target, effectId)` / `GetActiveBuffs(target)`

### 5.3 效果执行器 (EffectExecutor)

**6 种类型处理**:

| 类型 | 执行逻辑 |
|------|---------|
| Damage | 读取 DamageType → 计算防御减免 → 扣 HP → 死亡检测 |
| CC | 设置控制状态(Stun/Root/Slow/Knockup) → 修改 MoveSpeed/WalkSpeed → 到期恢复 |
| Shield | 创建护盾值 → 伤害先扣护盾 → 破碎或到期移除 |
| DoT | 每 TickInterval 执行一次 Damage 逻辑 |
| HoT | 每 TickInterval 回复 HP（预留） |
| StatMod | 修改目标属性(Flat/Percent) → 到期恢复原值 |

### 5.4 配置注册系统

**自动发现模式**:
```lua
-- HeroRegistry / SkillRegistry 核心逻辑
for _, module in folder:GetChildren() do
    if module:IsA("ModuleScript") then
        local ok, data = pcall(require, module)
        if ok then
            registry[data.id or data.heroId] = data
        else
            warn("[Registry] Failed:", module.Name, data)
        end
    end
end
```

**SkillModuleMap**: 服务端启动时构建 `{skillID → ModuleScript}` O(1) 查找表，避免运行时遍历。

### 5.5 大厅与匹配 (LobbyManager)

**玩家状态机**: `LOBBY` → `MATCHING` → `DUELING`

**匹配区域**: 圆柱体物理触发(半径 15, 中心 (-180,62,180))，防抖 0.5s

**掉线处理**: 匹配中移出队列；对决中通知 DuelManager 判负

### 5.6 对决系统 (DuelManager)

**生命周期**: CreateDuel → 3s 倒计时 → 分配阵营 → 传送 → 战斗 → 3 杀判定 → 5s 展示 → 回大厅

**阵营**: RedTeam/BlueTeam (BrickColor 区分, AutoAssignable=false)

### 5.7 被动系统 (PassiveSystem) ← REQ-007

| 属性 | 值 |
|------|-----|
| 需求ID | REQ-007 |
| 状态 | 🔄 开发中 |
| 技术文档 | [查看详情](.GameDev/REQ-007/03_技术设计.md) |

**驱动方式**: 事件驱动（非 Heartbeat tick），由 AutoAttackManager/EffectExecutor/MatchSystem 触发

**事件类型**: OnHit / OnDamaged / OnKill / Periodic / OnAbilityUse / OnHealthBelow

**数据结构**: `activePassives[player] = { [passiveId] = PassiveInstance }`

**核心流程**:
```
事件触发 (AutoAttackManager.OnHit / EffectExecutor.OnDamaged)
  → PassiveSystem:OnEvent(eventType, player, context)
  → 遍历 player 已注册被动
  → 匹配 TriggerEvent
  → 检查 Conditions (CooldownReady, HealthBelow, etc.)
  → BuffSystem:ApplyEffect(source, target, effectId)
  → 更新内置 CD
```

**API**:
- `RegisterPassives(player, heroId)` — 英雄装备时注册被动
- `UnregisterPassives(player)` — 英雄切换/离开时注销
- `OnEvent(eventType, player, context)` — 事件派发入口
- `IsPassiveOnCooldown(player, passiveId)` — CD 查询

**初始被动**: 后羿(5003 多重射击, OnHit 叠攻速) + 廉颇(5004 不屈意志, OnDamaged 加防)

**依赖**: BuffSystem (效果执行), PassiveConfig (数据), HeroRegistry (英雄被动关联)

### 5.8 能量系统 (EnergySystem) ← REQ-007

| 属性 | 值 |
|------|-----|
| 需求ID | REQ-007 |
| 状态 | 🔄 开发中 |
| 技术文档 | [查看详情](.GameDev/REQ-007/03_技术设计.md) |

**驱动方式**: `RunService.Heartbeat` 每帧 tick（自然恢复/怒气衰减）

**4 种能量类型**:

| 类型 | 初始值 | 恢复方式 | 衰减 | 显示 |
|------|--------|---------|------|------|
| Mana | 满值 | RegenPerSecond/s | 无 | 蓝色条 |
| Rage | 0 | 命中/受击获取 | 脱战5s后10/s | 红色条 |
| Energy | 满值 | 10/s 快速恢复 | 无 | 金色条 |
| None | — | — | — | 隐藏 |

**数据结构**: `energyStates[player] = { current, max, type, lastCombatTime, lastSynced }`

**同步策略**: SyncEnergyEvent (S→C)，0.5s 间隔 + 变化>5% 立即同步

**API**:
- `InitEnergy(player, heroId)` — 初始化能量
- `CanCast(player, cost)` — 检查能否施法
- `ConsumeEnergy(player, amount)` — 扣除能量
- `AddEnergy(player, amount, reason)` — 增加能量 (Rage)
- `GetEnergy(player)` — 查询 {current, max, type}
- `RemovePlayer(player)` — 清理

**集成点**:
- PlayerSkillManager: 施法前 CanCast() → 施法后 ConsumeEnergy()
- AutoAttackManager: 命中后 AddEnergy (Rage 类型)
- UI_HUD: SyncEnergyEvent 监听 → 动态颜色条

### 5.9 训练场系统 (TrainingManager) ← REQ-009

| 属性 | 值 |
|------|-----|
| 需求ID | REQ-009 |
| 状态 | 🔄 开发中 |
| 技术文档 | [查看详情](.GameDev/REQ-009/03_技术设计.md) |

**驱动方式**: 事件驱动 (RemoteEvent) + task.delay (假人 HP 回满)

**数据结构**: 
- `trainingStates[player] = { noCooldown: bool, noCost: bool }`
- `dummies[player] = { Model[] }` (每人最多 3)

**5 项功能**:

| 功能 | 实现方式 |
|------|---------|
| F1 开关CD | `shared.TrainingManager.IsNoCooldown()` → BaseSkill.CanCast/StartCooldown 检查 |
| F2 刷新HP/MP | Humanoid.Health=Max + MP回满 + EnergySystem回满 + BuffSystem.RemoveAllEffects |
| F3 训练假人 | R15 Dummy (Anchored, HP=10000, 不死, BillboardGui 血条, 5s HP回满) |
| F4 等级调整 | StatsManager.SetLevel → recalculateStats + HP回满 |
| F5 重置位置 | CFrame 传送出生点 + 附带 F2 |

**安全机制**:
- 所有操作仅 LOBBY 状态允许 (服务端验证 shared.LobbyManager.GetPlayerState)
- 进入 MATCHING/DUELING 时自动重置: noCooldown=false, noCost=false, 清除假人, 等级重置
- DuelManager.CreateDuel 双重检查: 调用 shared.TrainingManager.ResetTrainingState
- Rate limit: 0.2s/操作

**API**:
- `shared.TrainingManager.IsNoCooldown(player)` — BaseSkill 查询
- `shared.TrainingManager.IsNoCost(player)` — PlayerSkillManager 查询
- `shared.TrainingManager.ResetTrainingState(player)` — 强制重置

**依赖**: LobbyManager (状态查询), BaseSkill (CD检查), StatsManager (等级), BuffSystem (清Buff), EnergySystem (能量回满)

## 六、编码规范

### 6.1 文件组织
- 服务端逻辑: `ServerScriptService/` (`.server.lua` 自动运行，ModuleScript 按需 require)
- 客户端逻辑: `StarterPlayerScripts/` (`.client.lua` 自动运行)
- 共享数据: `ReplicatedStorage/` (Server+Client 均可 require)
- 不要在 `ReplicatedStorage` 中放服务端逻辑

### 6.2 Luau 代码风格
- **变量命名**: camelCase (局部变量/函数), PascalCase (模块名/类名), UPPER_SNAKE (常量)
- **ModuleScript 导出**: 返回 table，公共 API 使用 PascalCase 或 camelCase
- **nil 安全**: FindFirstChild 替代点号访问，pcall 保护 require，Guard Clause 提前返回
- **集合遍历**: 需修改时先收集再处理（BuffSystem 的 toExpire/toCleanTargets 模式）

### 6.3 性能规范
- **RunService.Heartbeat**: 只做必要的每帧逻辑（BuffSystem tick、位置同步）
- **Instance 创建**: 先设属性再设 Parent
- **范围检测**: 使用距离平方比较，避免 sqrt（CombatUtils 模式）
- **RemoteEvent**: 数据最小化，避免每帧发送

### 6.4 Rojo 约定
- 文件名即 Instance 名，避免特殊字符
- `.server.lua` → Script, `.client.lua` → LocalScript, `.lua` → ModuleScript
- `default.project.json` 中 `$path` 映射目录结构
