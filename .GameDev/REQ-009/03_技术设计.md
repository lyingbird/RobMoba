### 3.2 核心模块设计

#### TrainingManager.server.lua (新增, 服务端入口脚本)

**职责**: 训练场所有服务端逻辑的单一管理点

```
TrainingManager
├── 数据:
│   trainingStates[player] = {
│     noCooldown: boolean,  -- F1
│     noCost: boolean,      -- F1 (随 noCooldown 联动)
│     trainingLevel: number -- F4 (训练场覆盖等级)
│   }
│   dummies[player] = { Model[] }  -- F3, 最多3个
│
├── RemoteEvent 处理:
│   TrainingEvent.OnServerEvent → onTrainingAction(player, data)
│     data.action = "toggleCD" | "refreshHP" | "spawnDummy" | "clearDummies" | "setLevel" | "resetPos"
│
├── 操作实现:
│   toggleCD(player, enabled)    → 修改 trainingStates, sync
│   refreshHP(player)            → Humanoid.Health=Max + MP回满 + Energy回满 + RemoveAllEffects
│   spawnDummy(player)           → 创建 R15 Dummy, 注册, 启动 HP 回满 loop
│   clearDummies(player)         → 销毁所有假人
│   setLevel(player, level)      → 设置等级, recalculateStats
│   resetPosition(player)        → 传送到出生点 + refreshHP
│
├── 清理:
│   onStateChange(player, newState)  → MATCHING/DUELING 时重置所有训练设置
│   onPlayerRemoving(player)         → 清理 dummies + trainingStates
│
└── 对外 API (shared.TrainingManager):
    IsNoCooldown(player) → boolean
    IsNoCost(player) → boolean
    ResetTrainingState(player)
```

### 3.3 关键流程

#### F1: 开关技能冷却 时序

```
Client                          Server
  │                               │
  │  TrainingEvent:FireServer     │
  │  {action:"toggleCD",          │
  │   enabled:true}               │
  │ ─────────────────────────────→│
  │                               │ 验证: playerState == "LOBBY"
  │                               │ trainingStates[player].noCooldown = true
  │                               │ trainingStates[player].noCost = true
  │  TrainingSyncEvent:FireClient │
  │  {noCooldown:true,            │
  │   noCost:true, ...}           │
  │ ←─────────────────────────────│
  │                               │
  │  (玩家按技能)                 │
  │  CastSkillEvent:FireServer    │
  │ ─────────────────────────────→│
  │                               │ PlayerSkillManager:
  │                               │   skillInstance:CanCast()
  │                               │     → BaseSkill:CanCast()
  │                               │     → shared.TrainingManager.IsNoCooldown(player) == true
  │                               │     → return true (跳过CD检查)
  │                               │   noCost == true → 跳过 EnergySystem:ConsumeEnergy
  │                               │   skillInstance:StartCooldown()
  │                               │     → noCooldown == true → 跳过 (不设LastCastTime)
  │                               │   SyncCooldownEvent:FireClient(player, key, 0, skillId)
  │ ←─────────────────────────────│
  │  (客户端显示CD=0, 技能立即可用)
```

#### F3: 训练假人生命周期

```
Server: spawnDummy(player)
  │
  ├─ 1. 计算位置: player.Character.HumanoidRootPart.CFrame * CFrame.new(0,0,-10)
  │
  ├─ 2. 创建 Model "TrainingDummy"
  │     ├─ HumanoidRootPart (Anchored=true)
  │     ├─ Humanoid (MaxHealth=10000, Health=10000)
  │     ├─ R15 BodyParts (灰色 BrickColor)
  │     └─ BillboardGui (血条)
  │
  ├─ 3. 不死机制: Humanoid.HealthChanged → clamp Health ≥ 1
  │
  ├─ 4. HP 回满 loop: task.delay(5, function() Health = MaxHealth end) 循环
  │
  ├─ 5. 注册: table.insert(dummies[player], dummy)
  │     └─ 如果 #dummies[player] > 3 → 移除最早的
  │
  └─ 6. Sync → TrainingSyncEvent { dummyCount = #dummies[player] }
```

#### 状态切换清理

```
LobbyManager: playerStates[player] = "MATCHING" or "DUELING"
  │
  └─ TrainingManager 监听 (通过 shared.LobbyManager 轮询或 Attribute 桥):
       ├─ trainingStates[player] = { noCooldown=false, noCost=false }
       ├─ clearDummies(player)
       ├─ 重置等级为 1 + recalculateStats
       └─ TrainingSyncEvent:FireClient(player, { panelVisible=false, reset=true })
```

## 4. 接口设计

### 4.1 RemoteEvent 协议

#### TrainingEvent (C→S)

```lua
-- 客户端发送:
TrainingEvent:FireServer({
    action = string,  -- "toggleCD" | "refreshHP" | "spawnDummy" | "clearDummies" | "setLevel" | "resetPos"
    -- action-specific fields:
    enabled = boolean,  -- toggleCD only
    level = number,     -- setLevel only (1~MaxLevel)
})
```

#### TrainingSyncEvent (S→C)

```lua
-- 服务端发送:
TrainingSyncEvent:FireClient(player, {
    noCooldown = boolean,
    dummyCount = number,     -- 0~3
    level = number,          -- 当前训练等级
    panelVisible = boolean,  -- 面板是否显示
})
```

### 4.2 shared API

```lua
-- shared.TrainingManager (供 BaseSkill / PlayerSkillManager 查询)
shared.TrainingManager = {
    IsNoCooldown = function(player) → boolean,
    IsNoCost = function(player) → boolean,
    ResetTrainingState = function(player),  -- 供 LobbyManager/DuelManager 调用
}
```

### 4.3 BaseSkill 修改接口

```lua
-- BaseSkill:CanCast() 修改后:
function BaseSkill:CanCast(player)
    -- 训练场无CD检查
    if player and shared.TrainingManager and shared.TrainingManager.IsNoCooldown(player) then
        return true
    end
    return (os.clock() - self.LastCastTime) >= self:GetFinalCD()
end

-- BaseSkill:StartCooldown() 修改后:
function BaseSkill:StartCooldown(player)
    -- 训练场无CD: 不设置 LastCastTime
    if player and shared.TrainingManager and shared.TrainingManager.IsNoCooldown(player) then
        return
    end
    self.LastCastTime = os.clock()
end
```

### 4.4 PlayerSkillManager 修改接口

```lua
-- CastSkillEvent handler 中, noCost 检查:
-- 在 energyCost 检查之前加入:
local isNoCost = shared.TrainingManager and shared.TrainingManager.IsNoCost(player)
if not isNoCost then
    if energyCost > 0 and not EnergySystem:CanCast(player, energyCost) then
        return
    end
end
-- 在能量扣除处:
if not isNoCost and energyCost > 0 then
    EnergySystem:ConsumeEnergy(player, energyCost)
end
```

### 4.5 StatsManager 新增公开 API

```lua
-- 需要将 recalculateStats 暴露为公开方法:
function StatsManager.RecalculateStats(player)
    local character = player.Character
    if character then
        recalculateStats(character)
    end
end

-- 训练场等级调整调用:
function StatsManager.SetLevel(player, level)
    local character = player.Character
    if not character then return end
    character:SetAttribute("Level", level)
    player:SetAttribute("Level", level)
    recalculateStats(character)
    -- HP 回满 (等级调整后)
    local humanoid = character:FindFirstChildOfClass("Humanoid")
    if humanoid then
        humanoid.Health = humanoid.MaxHealth
        character:SetAttribute("HP", math.floor(humanoid.MaxHealth))
        character:SetAttribute("MP", character:GetAttribute("MaxMP"))
    end
end
```

## 6. 技术风险

| 风险 | 级别 | 概率 | 影响 | 应对措施 |
|------|------|------|------|---------|
| noCooldown/noCost 带入对决 | 🔴 高 | 低 | 破坏公平性 | **双重保障**: (1) TrainingManager 监听状态切换时强制重置; (2) DuelManager.CreateDuel 调用 `shared.TrainingManager.ResetTrainingState()` |
| BaseSkill.CanCast 签名变更 (新增 player 参数) | 🟡 中 | 中 | 现有调用点需同步更新 | 使用可选参数: `function CanCast(player)`, player 为 nil 时走原逻辑。PlayerSkillManager 是唯一调用方，改动可控 |
| 训练假人积累导致性能问题 | 🟡 中 | 低 | 多人服务器假人过多 | 每人上限 3 个 + 离开时清理 + 总量上限 (MAX_TOTAL_DUMMIES = 15) |
| StatsManager.recalculateStats 暴露后被误用 | 🟢 低 | 低 | 意外属性变化 | 仅通过 SetLevel 间接调用，RecalculateStats 作为内部 API 文档标注 |

## 9. 性能考量

| 关注点 | 预期指标 | 优化策略 |
|--------|----------|----------|
| 假人 HP 回满 tick | 每假人 1次/5s | 使用 `task.delay` 循环而非 Heartbeat, 假人销毁时终止 |
| TrainingEvent 频率 | ≤5 次/秒/玩家 | 服务端 rate limiter (1/0.2s debounce) |
| 假人 Instance 数量 | 每人最多 3, 全服最多 15 | 超限自动移除 |
| TrainingSyncEvent 频率 | 仅操作时发送 | 非持续同步, 无 Heartbeat 开销 |
| 新增 Heartbeat 连接 | 0 | 不使用 Heartbeat, 避免增加服务端帧开销 |
