## 7. 代码质量观测

### 7.1 良好实践 ✅

1. **延迟加载模式**: TrainingManager 使用 `getStatsManager()/getBuffSystem()/getEnergySystem()` 惰性加载，避免初始化顺序依赖
2. **Collect-then-process**: 状态监听循环先收集 `toReset` 再遍历重置，避免遍历中修改表
3. **双重安全机制**: noCooldown 泄漏防护 — 轮询监听 + shared API 直接调用
4. **向后兼容**: BaseSkill CanCast/StartCooldown 添加可选 player 参数，nil 时走原逻辑
5. **输入验证完备**: 服务端对 RemoteEvent 数据做 typeof 验证 + LOBBY 状态验证 + 英雄存在验证

### 7.2 次要观测 (不影响通过，建议后续优化)

| # | 观测 | 级别 | 建议 |
|---|------|------|------|
| O-1 | `refreshHP` 中能量回满使用 `AddEnergy(player, max, "training_refill")`，AddEnergy 是增量式的而非设置式。若当前能量已接近 max，可能因 min clamp 导致微小误差 | 🟢 信息 | EnergySystem 内部 `math.min(state.max, state.current + amount)` 正确 clamp，无实际问题。若后续新增 RefillEnergy API 可改用 |
