# 第一章 功能概述

## 1.1 问题分析

当前在手机端 (Device Emulator / 真机) 运行 RobMoba 时，UI存在以下严重问题：

### 问题清单

| # | 问题 | 根因 | 严重度 |
|---|------|------|--------|
| P1 | 手机端显示PC版HUD（底部居中技能栏、左侧英雄面板、右侧匹配按钮） | `Client.client.lua` L94 `UIManager.Init()` 无条件执行，不区分PC/Mobile | 🔴 |
| P2 | 移动端UI组件（摇杆/技能按钮）只在选完英雄后才出现 | 移动端UI初始化在 `onHeroConfirmed()` 内部（L132-192） | 🔴 |
| P3 | PC版HUD和移动端UI同时渲染，互相遮挡 | 没有根据 `isMobile` 条件隐藏PC版HUD | 🔴 |
| P4 | 训练场面板、匹配按钮在手机端位置/大小不适合触屏操作 | 这些辅助UI没有做移动端适配（REQ-011仅做了核心操控UI） | 🟡 |
| P5 | 大厅模式下没有王者荣耀风格的全局布局 | 缺少移动端专属的大厅UI层 | 🟡 |

### 截图对比

| 当前状态 | 目标状态（王者荣耀参考） |
|---------|----------------------|
| PC式底部技能栏 | 右侧弧形技能按钮 |
| 左侧文字英雄面板 | 左下虚拟摇杆 |
| 右侧"开始匹配"按钮 | 顶部居中信息栏 |
| 无摇杆/无触屏UI | 左上小地图+头像 |
| 所有元素混合叠加 | 底部居中装备栏 |

## 1.2 设计目标

| 目标 | 描述 | 优先级 |
|------|------|--------|
| PC/Mobile UI隔离 | `isMobile=true` 时隐藏PC版HUD，只显示移动端UI | P0 |
| 移动端大厅完整体验 | 大厅模式下就能看到移动端UI框架（摇杆区域指示、英雄选择、训练场按钮、匹配按钮） | P0 |
| 王者荣耀标准布局 | 所有移动端UI元素位置/大小对标王者荣耀，符合手机端操作人体工学 | P0 |
| 底层系统零改动 | MobileInputManager、MovementManager、CameraManager保持不变 | P0 |
| 服务端零改动 | 所有RemoteEvent协议不变 | P0 |

## 1.3 用户故事

作为一个**手机端 Roblox 玩家**，
我想要**从进入游戏第一秒就看到符合手机端MOBA标准的UI布局**（左下摇杆区、右下技能区、顶部信息栏、左上小地图），
以便**获得和王者荣耀一样的熟悉感和操控舒适度**。

## 2.2 MOD-A 移动端大厅UI适配

### 核心问题

`Client.client.lua` L94 无条件执行 `UIManager.Init()`，导致PC版HUD（UI_HUD + UI_Backpack + UI_DragDrop + UI_MatchButton）在手机端也完整渲染。

### 改造方案

**方案: PC/Mobile 条件分支**

```
Client.client.lua 启动流程改造:

原始（当前）:
  L94: UIManager.Init()           ← 始终初始化PC版HUD
  L95: OverheadUI.Init()
  L96: UI_TrainingPanel.Init()    ← 始终初始化训练场面板
  L97: StatsBinding.Init(UI_HUD)
  ...
  L211: HeroSelectUI.Show()       ← 始终弹出英雄选择

改造后:
  if isMobile then
    -- ===== 移动端路径 =====
    创建 MobileUI ScreenGui
    创建 MobileFrame
    初始化移动端大厅UI元素:
      - 英雄选择面板（复用HeroSelectUI，适配触屏布局）
      - 移动端训练场按钮（替代PC版UI_TrainingPanel）
      - 移动端匹配按钮（替代PC版UI_MatchButton）
    OverheadUI.Init()
    HeroSelectUI.Show()
    -- 注意: 摇杆/技能按钮仍在onHeroConfirmed中初始化（需要heroId）
  else
    -- ===== PC端路径（保持原样）=====
    UIManager.Init()
    OverheadUI.Init()
    UI_TrainingPanel.Init()
    StatsBinding.Init(UI_HUD)
    HeroSelectUI.Show()
  end
```

### 移动端大厅UI元素

| UI元素 | 位置 | 功能 |
|--------|------|------|
| 英雄选择面板 | 全屏覆盖（首次弹出） | 复用 `HeroSelectUI`（已支持触屏MouseButton1Click） |
| 移动端匹配按钮 | 右上角，SafeArea内 | 触屏友好的大按钮，功能同 `UI_MatchButton` |
| 移动端训练场按钮 | 左上角，SafeArea内 | 触屏友好，功能同 `UI_TrainingPanel` |
| 英雄小面板 | 左下角摇杆区上方 | 显示当前选择的英雄，复用 `HeroSelectUI.ShowMiniPanel()` |

### 移动端 StatsBinding

移动端不使用 PC 版 `UI_HUD`，因此 `StatsBinding.Init(UI_HUD)` 需要改为与移动端 HUD 绑定：
- `StatsBinding.Init(mobileHUD)` — 参数改为传入 `UI_MobileHUD` 返回的对象
- 或者 `StatsBinding` 自行检测并绑定对应的UI元素

## 2.3 MOD-B 虚拟摇杆布局优化

### 当前状态

`UI_VirtualJoystick.lua` 功能正确（死区/钳位/淡出），但存在以下布局问题：

| 问题 | 改造 |
|------|------|
| 摇杆只在 `onHeroConfirmed` 后初始化 | MOD-A 将初始化时机提前到大厅阶段 |
| 大厅模式下不可见 | 大厅模式下显示静态摇杆指示图（半透明） |

### 布局规格（王者荣耀标准）

| 参数 | 值 | 说明 |
|------|-----|------|
| 触摸激活区 | 屏幕左半区(X: 0~50%) | 左半屏任意位置按下激活 |
| 外圈直径 | 屏幕短边 25% | 例：iPhone 14 Pro → ~175px |
| 摇杆球直径 | 外圈 40% | ~70px |
| 死区 | 中心 15% | 防误触 |
| 默认位置 | 左下角 (15%, 75%) | 距底部25%，距左侧15% |
| 透明度(未激活) | 外圈 0.3, 球 0.5 | 静态指示不遮挡视野 |
| 透明度(激活中) | 外圈 0.5, 球 0.9 | 拖拽时高亮 |
| 淡出时间 | 0.3s | 松手后平滑淡出 |

### 大厅模式行为

- 大厅模式下虚拟摇杆**始终可见**（静态指示状态，半透明）
- 选完英雄后**激活摇杆输入功能**（`MobileInputManager.Init()` 后才响应移动）
- 未选英雄时，触摸摇杆区域无效果（摇杆UI不响应输入）

## 2.4 MOD-C 技能按钮弧形布局

### 布局规格（对标王者荣耀弧形排列）

```
                 [W]
              [Q]   [R]        ← 技能弧形
            [D] [F]            ← 召唤师技能（预留位置）
                 [ATK]         ← 普攻大按钮（最底部最大）
```

| 按钮 | 大小(屏幕短边比) | 位置锚点 | 说明 |
|------|-----------------|---------|------|
| ATK(普攻) | 14% | 右下 (88%, 82%) | 最大按钮，拇指最易触及 |
| R(大招) | 11% | ATK 左上 45° | 弧形，距ATK中心 130% ATK直径 |
| W | 11% | R 上方 | 弧形连续排列 |
| Q | 11% | W 左侧 | 弧形连续排列 |
| D(预留) | 8% | Q 左下方 | 召唤师技能1，当前项目暂未实现 |
| F(预留) | 8% | D 下方 | 召唤师技能2，当前项目暂未实现 |

### 弧形排列算法

```
以普攻按钮中心为圆心，半径R = 普攻按钮直径 × 1.3
技能按钮沿弧线排列：
  R键: 角度 = 135° (左上 45°)
  W键: 角度 = 165° (继续左上)  
  Q键: 角度 = 195° (再继续)
按钮间距: 约 30° 弧度
```

### 技能按钮状态

| 状态 | 视觉表现 | 交互 |
|------|---------|------|
| 可用 | 正常图标 + 高亮边框 | 可按/可拖拽瞄准 |
| CD中 | 灰色遮罩 + 倒计时数字 + 顺时针扫描动画 | 不可点击 |
| MP不足 | 蓝色闪烁边框 | 不可点击 |
| 未学习(无技能) | 锁定图标 + 半透明 | 不可交互 |
| 大厅模式(未选英雄) | 空白圆形 + 问号 | 不可交互 |

### 方向轮盘瞄准（保持REQ-011设计）

指向性技能(aimType="directional"/"area")按住后弹出方向轮盘，拖拽选方向，松手释放。此逻辑REQ-011已实现，本次不改动。

## 2.9 边界条件与异常处理

| 场景 | 处理方式 |
|------|---------|
| 未选英雄时触摸摇杆区 | 摇杆UI不响应（需选完英雄并初始化MobileInputManager后才激活） |
| 未选英雄时触摸技能按钮 | 显示"请先选择英雄"提示 |
| 对战中切出到大厅 | 保持移动端UI状态，对战结束后恢复大厅UI |
| 屏幕旋转(竖屏) | 不支持，强制横屏（Roblox默认行为） |
| 多种分辨率适配 | 所有尺寸用 Scale(比例) 而非 Offset(像素)，参数比例化 |
| 安全区域被遮挡 | 使用 SafeArea padding 确保所有UI在安全区内 |
| PC端不受影响 | `isMobile=false` 时走原有PC路径，PC版UI完全不变 |
| DEBUG_FORCE_MOBILE=true | PC上模拟移动端，显示移动端UI（调试用） |
