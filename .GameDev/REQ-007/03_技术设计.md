### 3.2 PassiveSystem 事件流

```
普攻命中 (AutoAttackManager)
  → PassiveSystem:OnEvent("OnHit", player, target, {damage=X, type="Physical"})
    → 遍历 player 注册的被动
    → 检查 TriggerEvent == "OnHit"
    → 检查 Conditions (CooldownReady, etc.)
    → BuffSystem:ApplyEffect(source, target_or_self, effectId)
    → 更新内置 CD

技能伤害 (EffectExecutor._executeDamage)
  → PassiveSystem:OnEvent("OnDamaged", target_player, source, {damage=X, type="Magic"})
    → 同上流程（目标视角触发）

击杀 (MatchSystem / DuelManager 击杀检测)
  → PassiveSystem:OnEvent("OnKill", killer_player, victim, {})
```

### 3.3 EnergySystem Heartbeat tick

```
每帧 (RunService.Heartbeat):
  for player, energyData in energyStates:
    if energyData.type == "Mana" or energyData.type == "Energy":
      → 自然恢复: current += regenPerSecond * dt
      → clamp(0, max)
    
    if energyData.type == "Rage":
      → 检查脱战时间: now - lastCombatTime > DecayDelay?
        → 衰减: current -= decayRate * dt
        → clamp(0, max)
    
    → 如果 |current - lastSynced| > syncThreshold (5%):
      → SyncEnergyEvent:FireClient(player, {current, max, type})
      → lastSynced = current
```

## 4. 接口设计

### 4.1 PassiveSystem API

```lua
-- PassiveSystem.lua (ServerModules/)
local PassiveSystem = {}

-- 初始化: 为玩家注册英雄被动
function PassiveSystem:RegisterPassives(player, heroId)
-- 清除: 注销所有被动 (英雄切换/离开时)
function PassiveSystem:UnregisterPassives(player)
-- 事件派发: 由 AutoAttackManager/EffectExecutor/MatchSystem 调用
function PassiveSystem:OnEvent(eventType, player, context)
-- 查询: 某被动是否在 CD
function PassiveSystem:IsPassiveOnCooldown(player, passiveId)

return PassiveSystem
```

### 4.2 EnergySystem API

```lua
-- EnergySystem.lua (ServerModules/)
local EnergySystem = {}

-- 初始化: 为玩家设置能量类型
function EnergySystem:InitEnergy(player, heroId)
-- 检查: 能否施放 (能量 >= cost)
function EnergySystem:CanCast(player, cost)
-- 消耗: 扣除能量
function EnergySystem:ConsumeEnergy(player, amount)
-- 增加: 战斗获取 (Rage 专用)
function EnergySystem:AddEnergy(player, amount, reason)
-- 查询: 获取当前能量状态
function EnergySystem:GetEnergy(player)
-- 清理: 移除玩家能量数据
function EnergySystem:RemovePlayer(player)

return EnergySystem
```

### 4.3 新增 RemoteEvent

## 6. 技术风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| PassiveSystem OnHit 高频调用 | 性能 | 低 | 内置 CD + 条件检查提前返回; 30 英雄 × 1 被动 = 30 次 table 查找/次命中，微不足道 |
| EnergySystem Heartbeat 持续 tick | 性能 | 低 | 与 BuffSystem 共存（已验证 Heartbeat 可承受），能量只有整数运算 |
| UI_HeroSelect Grid 布局 30+ 卡片 | 性能 | 极低 | Roblox ScrollingFrame 原生支持，30 个 Frame 实例无压力 |
| SyncEnergyEvent 同步频率 | 带宽 | 低 | 0.5s + 阈值(5%)双重节流，最坏 2 次/秒/玩家 |

## 7. 与现有系统集成

| 依赖系统 | 集成方式 | 注意事项 |
|----------|----------|----------|
| BuffSystem | PassiveSystem 调用 `BuffSystem:ApplyEffect()` | 标准 API，零修改 |
| EffectConfig | 新增 3080/3081/3082 三个效果条目 | ID 范围在 3080-3099（后羿/廉颇被动段） |
| PlayerSkillManager | 施法前插入 `EnergySystem:CanCast()` 检查 | 在 `skillInstance:CanCast()` 之后、`OnCast()` 之前 |
| AutoAttackManager | 普攻命中后 `PassiveSystem:OnEvent("OnHit", ...)` | 在 `TakeDamage()` 之后添加一行 |
| EffectExecutor | `_executeDamage()` 中触发 OnDamaged | 在 `_applyDamageAfterShield()` 之后添加 |
| StatsManager | 无直接集成 | 被动 StatMod 走 BuffSystem → EffectExecutor 标准流程 |
