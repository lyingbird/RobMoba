# 第一章 功能概述

为 30+ 英雄批量接入奠定最后一块基础能力：**英雄选择 UI 可容纳大量卡片 + 被动系统赋予英雄独特性 + 能量系统实现差异化施法约束**。完成后，新增英雄预期降至 **0.8 天/英雄**。

## 1.1 设计目标

| 目标 | 描述 | 优先级 |
|------|------|--------|
| UI 可扩展 | 英雄选择界面从水平列表改为网格+滚动，支持 30+ 英雄卡片无性能问题 | P0 |
| 职业筛选 | 按职业分类 Tab 快速定位英雄（全部/法师/射手/坦克/刺客/辅助/战士） | P0 |
| 被动系统 | 事件驱动的被动技能框架，让每个英雄拥有独特的被动能力（参考王者荣耀被动设计） | P0 |
| 能量类型多样化 | 支持 Mana/Rage/Energy/None 4 种能量类型，不同英雄有不同施法资源 | P0 |
| 能量条 UI 适配 | HUD 能量条根据英雄能量类型自动切换颜色和显示名称 | P1 |
| 难度星级 | 英雄卡片上显示难度星级，帮助新手选择适合的英雄 | P1 |

## 1.2 用户故事

1. 作为一个 **新手玩家**，我想要在英雄选择界面看到 **难度星级** 和 **职业分类**，以便快速找到适合自己的英雄。
2. 作为一个 **玩家**，我想要感受每个英雄 **独特的被动能力**（如后羿叠加攻速、廉颇受击减伤），以便体验不同英雄的差异化乐趣。
3. 作为一个 **策划/程序**，我想要通过 **配置文件** 就能给新英雄添加被动和能量类型，以便快速量产英雄（0.8天/英雄）。

## MOD-A: 英雄选择 UI 改造

### A.1 核心机制

将现有 `UI_HeroSelect.lua` 的英雄卡片容器从 **UIListLayout (Horizontal)** 改为 **UIGridLayout + ScrollingFrame**，并添加职业分类 Tab 筛选栏和难度星级显示。

**当前问题**：`UIListLayout` 水平排列，5 张卡片已占满一屏（180px × 5 + 24px × 4 = 996px），30+ 张卡片需要 6120px 无法容纳。

**改造方案**：

```
┌──────────────────────────────────────────────────────────┐
│                     选择英雄                               │
│                  SELECT YOUR HERO                         │
├──────────────────────────────────────────────────────────┤
│  [全部(N)] [法师] [射手] [坦克] [刺客] [辅助] [战士]       │  ← 职业 Tab 筛选栏
├──────────────────────────────────────────────────────────┤
│ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐  │
│ │ ◉ 安琪拉│ │ ◉ 拉克丝│ │ ◉ 后 羿│ │ ◉ 廉 颇│ │ ◉ 赵 云│  │  ← Row 1
│ │  法师   │ │  法师   │ │  射手   │ │  坦克   │ │  战士   │  │
│ │ ★★☆   │ │ ★★★   │ │ ★☆☆   │ │ ★★☆   │ │ ★★★   │  │
│ │ Q W R  │ │ Q W E R│ │ Q W R  │ │ Q W R  │ │ Q W R  │  │
│ └────────┘ └────────┘ └────────┘ └────────┘ └────────┘  │
│ ┌────────┐ ┌────────┐ ...                                │
│ │ ◉ 妲 己│ │ ◉ 鲁 班│                                    │  ← Row 2+
│ │  法师   │ │  射手   │                                    │
│ │ ★☆☆   │ │ ★☆☆   │                                    │
│ └────────┘ └────────┘                                    │
│                    ▼ 向下滚动查看更多                       │  ← ScrollingFrame
├──────────────────────────────────────────────────────────┤
│              [ 🔒 锁定选择 ]                               │
└──────────────────────────────────────────────────────────┘
```

### A.2 布局参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 卡片尺寸 | 160 × 240 px | 比现有 180×280 略小，适配网格密度 |
| 网格列数 | 5 列 | 每行 5 张卡片，标准 1080p 宽度适配 |
| 卡片间距 | 16 px (H) / 16 px (V) | UIGridLayout.CellPadding |
| 滚动区域高度 | 0.6 (相对屏幕) | ScrollingFrame 占屏幕高度 60% |
| 滚动条 | 右侧细条，半透明 | ScrollBarThickness = 4, 半透明 |
| Tab 栏高度 | 40 px | 位于标题下方、卡片区域上方 |

### A.3 职业 Tab 筛选

**Tab 定义**（从 HeroRegistry 自动统计数量）：

| Tab 名称 | 匹配 Role 值 | 图标 |
|----------|-------------|------|
| 全部 | （不筛选） | 无 |
| 法师 | "Mage" | 🔮 |
| 射手 | "Marksman" | 🏹 |
| 坦克 | "Tank" | 🛡️ |
| 刺客 | "Assassin" | 🗡️ |
| 辅助 | "Support" | 💚 |
| 战士 | "Fighter" | ⚔️ |

**筛选逻辑**:
1. 默认选中"全部"Tab，显示所有 `Enabled ~= false` 的英雄
2. 点击职业 Tab 后，只显示该 Role 的英雄
3. Tab 上显示该职业的英雄数量，如"法师(8)"
4. 筛选后卡片重新排列（Grid 自动布局），ScrollingFrame CanvasSize 自动调整
5. 切换 Tab 时重置滚动位置到顶部

**Tab 数量为 0 的职业处理**: 仍然显示 Tab 但灰色不可点击（暗示未来会有该职业英雄）

### A.4 英雄卡片改造

在现有卡片基础上新增：

1. **职业标签**: 卡片名字下方，显示中文职业名（法师/射手/坦克/刺客/辅助/战士），字体 10px，颜色 Theme.TEXT_MID
2. **难度星级**: 职业标签下方，显示 ★ 星标（1-3 星），金色 `Color3.fromRGB(255, 200, 50)`
   - Difficulty=1: ★☆☆
   - Difficulty=2: ★★☆
   - Difficulty=3: ★★★

**职业中文名映射**:

| Role 值 | 中文显示 |
|---------|---------|
| Mage | 法师 |
| Marksman | 射手 |
| Tank | 坦克 |
| Assassin | 刺客 |
| Support | 辅助 |
| Fighter | 战士 |

### A.5 边界条件

| 场景 | 处理 |
|------|------|
| 英雄数 ≤ 5 | 网格单行居中，不显示滚动条 |
| 英雄数 > 25 | ScrollingFrame 自动滚动，CanvasSize 根据行数动态计算 |
| 筛选结果为 0 | 卡片区域显示居中文字"暂无此职业英雄" |
| 屏幕分辨率较低 | UIScale 自动适配（现有 Theme.autoScale 机制） |
| 已确认英雄被筛选隐藏 | 不影响锁定状态，切回"全部"Tab 可看到绿色高亮 |

## MOD-B: 被动系统

### B.1 设计理念

**参考王者荣耀被动设计哲学**: 被动技能定义英雄独特性，是区分英雄"手感"的核心。

- **后羿被动 (HOK 参考)**: 普攻叠加攻速，鼓励持续输出 → 定义射手"不动如山"站撸风格
- **廉颇被动 (HOK 参考)**: 受击减伤/回血，越打越肉 → 定义坦克"打不死"体验
- **安琪拉被动 (HOK 参考)**: 技能命中增加法强，鼓励连招 → 定义法师"一套带走"节奏
- **拉克丝被动 (LOL 参考)**: 技能标记目标，普攻触发额外伤害 → 鼓励普攻穿插连招

### B.2 被动系统架构

```
PassiveConfig.lua (配置层)
  │  定义所有被动: ID、触发事件、条件、效果引用、冷却
  │
  ▼
PassiveSystem.lua (运行时)
  │  事件监听 → 条件检查 → 效果执行
  │  使用 BuffSystem:ApplyEffect() 执行效果
  │
  ▼
HeroConfig (关联层)
  │  Passives = { [1] = 5003 }  ← 英雄被动 ID 引用
  │
  ▼
PlayerSkillManager (集成层)
  │  英雄装备时自动注册被动
  │  英雄切换时注销旧被动、注册新被动
```

### B.3 PassiveConfig 数据结构

```lua
-- PassiveConfig.lua
return {
    -- 后羿被动: 多重射击 — 连续命中叠加攻速
    [5003] = {
        Name = "多重射击",
        DisplayName = "多重射击",
        Description = "普攻命中叠加攻速，最多5层",
        TriggerEvent = "OnHit",          -- 触发事件
        Conditions = {},                  -- 无额外条件
        Effects = { 3080 },              -- 引用 EffectConfig: 攻速增加
        StackBehavior = {
            MaxStacks = 5,               -- 最多 5 层
            StackEffect = 3080,          -- 每层效果
            DecayDelay = 3,              -- 3秒无命中开始衰减
            DecayRate = 1,               -- 每秒衰减 1 层
        },
        Cooldown = 0,                    -- 无内置 CD
        Icon = "",                       -- 被动图标（预留）
    },

    -- 廉颇被动: 不屈意志 — 受击时获得减伤
    [5004] = {
        Name = "不屈意志",
        DisplayName = "不屈意志",
        Description = "受到伤害时获得短暂减伤效果",
        TriggerEvent = "OnDamaged",      -- 触发事件
        Conditions = {
            Logic = "AND",
            { Type = "CooldownReady" },  -- 内置 CD 就绪
        },
        Effects = { 3081 },              -- 引用 EffectConfig: DEF+MR 临时增加
        Cooldown = 8,                    -- 8秒内置 CD
    },
}
```

### B.4 触发事件类型

| 事件 | 触发时机 | 参数 | 典型用例 |
|------|---------|------|---------|
| OnHit | 普攻/技能**命中**目标时 | target, damageAmount, damageType | 后羿叠攻速、拉克丝标记 |
| OnDamaged | **受到**伤害时 | source, damageAmount, damageType | 廉颇减伤、护盾触发 |
| OnKill | **击杀**敌方英雄时 | target | 击杀回血、攻击力叠加 |
| Periodic | **每 N 秒**自动触发 | — | 回血/光环/持续检测 |
| OnAbilityUse | **释放技能**时 | skillID | 安琪拉法强叠加 |
| OnHealthBelow | **血量低于阈值**时（一次性触发，CD后可再触发） | threshold (0~1) | 低血量护盾/加速 |

### B.5 条件系统

| 条件类型 | 参数 | 说明 |
|---------|------|------|
| CooldownReady | — | 内置 CD 已就绪 |
| HealthBelow | threshold (0~1) | 自身血量低于百分比 |
| HealthAbove | threshold (0~1) | 自身血量高于百分比 |
| TargetIsHero | — | 目标必须是英雄（非NPC/木桩） |
| HasBuff | buffId | 自身拥有指定 buff |
| NotHasBuff | buffId | 自身没有指定 buff |

**条件组合**: 支持 `Logic = "AND"` 或 `Logic = "OR"`，最多 3 个条件。

### B.6 初始被动设计（2 个英雄验证）

#### 🟠 后羿 — 多重射击 (ID: 5003)

| 参数 | 值 | 说明 |
|------|-----|------|
| 触发事件 | OnHit | 普攻或技能命中 |
| 效果 | StatMod (AtkSpeed +10%/层) | 引用 EffectConfig 3080 |
| 叠加 | Stack, 最多 5 层 (= +50% AtkSpeed) | |
| 衰减 | 3 秒无命中后，每秒衰减 1 层 | |
| 内置CD | 0 (每次命中都触发) | |

**参考**: 王者荣耀后羿被动"惩戒射击"——普攻每叠一层增加 4% 攻速，满层(8层) 32%。我们简化为 5 层 × 10% = 50%（Roblox 快节奏适配）。

#### 🔵 廉颇 — 不屈意志 (ID: 5004)

| 参数 | 值 | 说明 |
|------|-----|------|
| 触发事件 | OnDamaged | 受到伤害时 |
| 条件 | CooldownReady | 8 秒内置 CD |
| 效果 | StatMod (DEF +30, MR +20, Duration 3s) | 引用 EffectConfig 3081 |
| 叠加 | Replace (刷新持续时间) | |
| 内置CD | 8 秒 | |

**参考**: 王者荣耀廉颇被动"坚韧"——受伤后获得短暂护甲和魔抗提升。简化为固定 DEF/MR 加成，无需百分比计算。

### B.7 对应 EffectConfig 条目（需新增）

```lua
-- 廉颇被动: 受击减伤
```

### B.8 HeroConfig 集成

英雄配置中新增 `Passives` 字段：

```lua
-- Heroes/HouYi.lua 新增字段
Passives = { [1] = 5003 },  -- 被动: 多重射击

-- Heroes/LianPo.lua 新增字段
Passives = { [1] = 5004 },  -- 被动: 不屈意志

-- 无被动英雄 (暂时)
-- Heroes/Angela.lua, Heroes/Lux.lua
-- Passives = {},  (字段可省略，系统按空处理)
```

### B.9 边界条件

| 场景 | 处理 |
|------|------|
| 英雄无被动（Passives 为空或不存在） | PassiveSystem 跳过注册，无任何影响 |
| 多个被动（Passives 有多条） | 每条独立注册、独立触发、独立 CD |
| 被动效果与技能效果叠加 | 走 BuffSystem 标准叠加规则，与技能效果无特殊交互 |
| 英雄死亡 | 所有被动暂停，复活后重新激活 |
| 英雄切换（大厅） | 旧被动注销、新被动注册 |
| 被动 CD 期间英雄切换 | CD 重置（切换即重置） |
| OnHit 自身技能（如 HouYi Q 增强普攻） | 可触发 OnHit 被动 |

## MOD-C: 能量系统

### C.1 设计理念

**参考王者荣耀/LOL 能量多样化**: 不同英雄使用不同资源施法，增加策略深度。

| 能量类型 | HOK/LOL 典型英雄 | 核心体验 |
|---------|-----------------|---------|
| **Mana** (法力) | 安琪拉、拉克丝、后羿 | 持续消耗，需要管理蓝量 |
| **Rage** (怒气) | 廉颇、典韦 | 空怒开局，战斗中积累，鼓励主动进攻 |
| **Energy** (能量) | 阿珂、兰陵王 | 固定100上限快速恢复，技能CD才是约束 |
| **None** (无消耗) | 蔡文姬 | 纯 CD 约束，简化操作 |

### C.2 EnergyConfig 数据结构

```lua
-- EnergyConfig.lua
return {
    Mana = {
        DisplayName = "法力",
        BaseMax = 500,
        GrowthPerLevel = 40,
        RegenPerSecond = 5,
        RegenGrowth = 0.5,
        BarColor = Color3.fromRGB(50, 100, 255),      -- 蓝色
```

### C.3 EnergySystem 核心机制

**数据流**:
```
EnergyConfig (配置) → EnergySystem.lua (服务端运行时)
    │
    ├── InitEnergy(player, heroId)        → 读取 HeroConfig.EnergyType → 初始化
    ├── ConsumeEnergy(player, amount)     → 技能释放前检查 + 扣除
    ├── CanCast(player, cost)             → 判断能否释放（能量≥消耗）
    ├── AddEnergy(player, amount, reason) → 被动/命中获得能量
    ├── GetEnergy(player)                 → 返回 {current, max, type}
    └── Heartbeat tick                    → 自然恢复 / 怒气衰减
```

**能量回复规则**:

| 类型 | 自然回复 | 战斗获取 | 脱战衰减 | 初始值 |
|------|---------|---------|---------|--------|
| Mana | ✅ RegenPerSecond/s | ❌ | ❌ | BaseMax (满蓝开局) |
| Rage | ❌ | ✅ GainOnHit/GainOnDamaged/GainOnSkillHit | ✅ DecayAfterCombat | 0 (空怒开局) |
| Energy | ✅ RegenPerSecond/s | ❌ | ❌ | BaseMax (满能量开局) |
| None | — | — | — | — |

### C.4 技能消耗集成

**SkillConfig 新增字段**: 每个技能可配置 `EnergyCost`（能量消耗量），默认为 0。

```lua
-- SkillConfig 示例
[1012] = {
    Name = "LianPoQ",
    CD = 8,
    Range = 30,
    EnergyCost = 20,           -- ← 新增：消耗 20 怒气
    ...
},
```

**施法流程变更**:
```
玩家按下技能键
  → PlayerSkillManager 检查 CD ✅
  → PlayerSkillManager 检查 EnergySystem.CanCast(player, cost) ✅
  → 执行技能
  → EnergySystem.ConsumeEnergy(player, cost)
  → 同步客户端能量条

若能量不足:
  → 拒绝施法
  → 客户端提示 "能量不足" (复用现有 ShowWarning)
```

### C.5 HeroConfig 集成

英雄配置中新增 `EnergyType` 字段：

```lua
-- 当前 4 英雄的能量类型分配
Angela   → EnergyType = "Mana"     -- 法师用法力
Lux      → EnergyType = "Mana"     -- 法师用法力
HouYi    → EnergyType = "Mana"     -- 射手用法力
LianPo   → EnergyType = "Rage"     -- 坦克用怒气
```

> 💡 [假设] 后羿使用 Mana 而非 Energy，因为射手在王者荣耀中使用法力是主流设定。后续可调整。

### C.6 HUD 能量条适配

**改造点**: `UI_HUD.lua` 中现有的 MpBar（蓝色固定）改为动态颜色和文字：

| 当前 | 改造后 |
|------|--------|
| 固定蓝色 (MP_BLUE) | 根据 EnergyType 读取 EnergyConfig.BarColor |
| 固定文字 "350/500" | 根据 ShowText 显示 "65/100" 或隐藏 |
| 始终显示 | None 类型时隐藏能量条 |

**同步协议**: 新增 `SyncEnergyEvent` (S→C)，数据格式:
```lua
{
    current = 65,
    max = 100,
    energyType = "Rage",
}
```

> 每 0.5 秒同步一次 或 能量变化 > 5% 时立即同步（避免频繁 Fire）。

### C.7 边界条件

| 场景 | 处理 |
|------|------|
| Mana 满蓝时继续恢复 | 不超过 Max，忽略多余回复量 |
| Rage 满怒时继续受击 | 不超过 Max |
| Rage 0 怒时技能消耗 > 0 | 拒绝施法 + ShowWarning |
| None 类型英雄技能有 EnergyCost | 忽略消耗（None = 无限资源） |
| 英雄死亡 | Mana/Energy 保持当前值，Rage 重置为 0 |
| 英雄切换（大厅） | 能量重新初始化为该类型初始值 |
| 等级提升 | Mana 的 MaxMP 增长，当前 MP += GrowthPerLevel |
| 技能 EnergyCost 为 0 或不存在 | 无消耗，正常释放 |
