# 第一章 功能概述

为 30+ 英雄的量产扩展奠定基础设施：将分散的配置集中化、将内联的效果系统化、将硬编码的注册自动化。

## 1.1 设计目标

| 目标 | 描述 | 优先级 |
|------|------|--------|
| 消除硬编码英雄列表 | HeroConfig 成为唯一数据源，UI_HeroSelect 和 GameManager 自动派生 | P0 |
| 配置文件拆分 | 将 HeroConfig/SkillConfig 按英雄拆分为独立文件，支持并行开发 | P0 |
| 自动注册机制 | 新增英雄/技能文件后自动被系统识别，零硬编码注册 | P0 |
| EffectConfig 效果配置体系 | 6 种标准效果类型（Damage/CC/Shield/DoT/HoT/StatMod）统一定义 | P0 |
| BuffSystem 运行时管理 | 替代 task.delay 手动管理，支持叠加/互斥/刷新/持续时间/Tick | P0 |
| 向后兼容 | 重构期间现有 4 英雄 15 技能功能完全不受影响 | P0 |
| HeroConfig 元数据扩展 | 新增 Role/Difficulty/SortOrder/Enabled/Tags 为后续 UI 改造做准备 | P1 |

## 1.2 用户故事

**策划视角**:
作为一个**策划**，
我想要**通过在 EffectConfig 中定义标准效果（伤害/减速/眩晕等），然后在技能配置中引用效果 ID**，
以便**设计新英雄技能时不需要每次都跟程序沟通减速/眩晕的具体实现方式**。

**程序视角**:
作为一个**开发者**，
我想要**新增英雄只需创建 Heroes/XX.lua 和 Skills/XX_Skills.lua 两个文件，系统自动发现和注册**，
以便**不再需要手动修改 3+ 处硬编码列表，避免遗漏导致 bug**。

**玩家视角**:
作为一个**玩家**，
我想要**技能效果（减速/眩晕/护盾等）表现一致且可靠**，
以便**不会遇到"被减速后速度恢复不了"或"护盾不消失"这类 bug**。

### 2.1.2 HeroRegistry 自动发现机制

**核心原理**: 扫描 `Heroes/` 目录下所有 ModuleScript，自动 require 并汇聚为统一配置表。

**行为规则**:
1. 启动时（模块首次 require 时）遍历 `Heroes/` 目录
2. 对每个 `ModuleScript` 执行 `require()`，获取英雄数据 table
3. 以 `HeroID` 字段为 key 注册到总表
4. 跳过 `Enabled = false` 的英雄（灰度发布支持）
5. 对外接口与原 `HeroConfig` 完全一致：`HeroRegistry[heroName]` 返回英雄数据

**单个英雄文件规范**:

每个 `Heroes/XX.lua` 必须返回一个 table，包含以下字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| HeroID | string | ✅ | 英雄唯一标识，必须与文件名一致 |
| DisplayName | string | ✅ | 中文显示名 |
| Theme | Color3 | ✅ | 主题色 |
| Role | string | ✅ | 职业：Mage/Marksman/Tank/Assassin/Support/Fighter |
| Difficulty | number | ✅ | 难度星级 1-3 |
| SortOrder | number | ✅ | 选人界面排序权重，数字越小越靠前 |
| Enabled | boolean | ✅ | 是否启用 |
| Tags | table | 选填 | 特性标签，如 { "Burst", "Control" } |
| FreeRotation | boolean | 选填 | 是否在免费轮换中，默认 false |
| Skills | table | ✅ | 技能槽映射 { Q = skillID, W = skillID, R = skillID } |
| BaseHP / BaseAttack 等 | number | ✅ | 基础属性（沿用现有字段） |
| Accessory | table | 选填 | 装饰物配置 |
| Poses | table | ✅ | 动画姿态数据 |
| CastDurations | table | ✅ | 技能施法时长 |
| CastLift | table | 选填 | 施法抬升 |
| MoveLock | table | 选填 | 移动锁定 |

### 2.1.3 SkillRegistry 自动发现机制

**核心原理**: 与 HeroRegistry 相同模式，扫描 `Skills/` 目录。

**行为规则**:
1. 遍历 `Skills/` 目录，每个 ModuleScript 返回一个 table（以 skillID 为 key 的技能配置合集）
2. 汇聚所有英雄的技能配置到统一查找表
3. 对外接口与原 `SkillConfig` 完全一致：`SkillRegistry[skillID]` 返回技能数据

**单个英雄技能文件规范**:

每个 `Skills/XX_Skills.lua` 返回一个 table，key 为 skillID（number），value 为技能配置：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| Name | string | ✅ | 技能内部名 |
| UIName | string | ✅ | 中文显示名 |
| Icon | string | ✅ | 图标资源 ID |
| BaseCD | number | ✅ | 基础冷却时间(秒) |
| BaseRange | number | ✅ | 基础施放距离 |
| BaseDamage | number | 选填 | 基础伤害 |
| Speed | number | 选填 | 弹道速度 |
| 其他现有字段 | any | 保持 | 保持现有 SkillConfig 中的所有自定义字段不变 |

> ⚠️ 本阶段 **不做** SkillConfig 字段标准化（那是 REQ-006 的工作），只做文件拆分和自动汇聚。现有的 ad-hoc 字段（StunDuration/VortexRadius 等）原封不动迁移。

### 2.1.4 消除硬编码英雄列表

**改造点 1: UI_HeroSelect.lua**

将 `HERO_ORDER = { "Angela", "Lux", ... }` 硬编码改为从 HeroRegistry 自动派生：
- 遍历 HeroRegistry，过滤 `Enabled ~= false` 的英雄
- 按 `SortOrder` 升序排列
- Test 英雄通过 `Enabled = false` 或 `Tags = {"Debug"}` 控制是否显示

**改造点 2: GameManager.server.lua**

将 `DEFAULT_HEROES = { ... }` 硬编码改为从 HeroRegistry 自动派生：
- 遍历 HeroRegistry，过滤 `Enabled ~= false` 且非 Test 英雄
- 结果用于服务端英雄校验

**改造点 3: LobbyManager.server.lua**

将 `HeroConfig[data.heroId]` 引用改为 `HeroRegistry[data.heroId]`

### 2.1.5 SkillModuleMap 查找表

**改造点**: PlayerSkillManager.server.lua

将 `FindFirstChild("Skill_" .. skillID)` 改为启动时建立的查找表：
- 启动时遍历 `Skills/` 文件夹，按 `Skill_{id}` 模式解析
- 建立 `{skillID → ModuleScript}` 映射
- 装备技能时 O(1) 查找，不再使用 FindFirstChild

## 2.2 模块B: EffectConfig 效果配置

### 2.2.1 效果类型定义

6 种标准效果类型，覆盖 MOBA 游戏核心效果需求：

| 类型 | 说明 | 王者荣耀参考 | 关键参数 |
|------|------|-------------|----------|
| **Damage** | 即时伤害 | 技能直接伤害 | DamageType(Physical/Magic/True), Amount, ScalesWith |
| **CC** | 控制效果 | 眩晕/减速/定身/击飞/沉默/缴械 | CCType, Duration, Percent(减速用) |
| **Shield** | 护盾 | 护盾抵消伤害 | Amount, Duration, ScalesWith |
| **DoT** | 持续伤害 | 灼烧/中毒 | TickDamage, TickInterval, Duration |
| **HoT** | 持续回复 | 回复/吸血 | TickHeal, TickInterval, Duration |
| **StatMod** | 属性修改 | 攻速/移速增减 | Stat, ModType(Flat/Percent), Value, Duration |

### 2.2.2 效果数据结构

每个效果条目的标准字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| Type | string | ✅ | 效果类型（上述 6 种之一）|
| Duration | number | 条件 | 持续时间(秒)，Damage 类型不需要 |
| Stacking | string | 选填 | 叠加规则：Replace/Stack/Refresh/Independent，默认 Replace |
| MaxStacks | number | 选填 | 最大叠加层数（仅 Stack 模式），默认 1 |
| MutexGroup | string | 选填 | 互斥组名（同组效果互相覆盖）|
| GrowthPerLevel | table | 选填 | 每级成长值 |
| ScalesWith | table | 选填 | 属性加成 { { Stat = "AP", Ratio = 0.6 } } |

**类型特有字段**:

| 类型 | 特有字段 |
|------|---------|
| Damage | DamageType, Amount |
| CC | CCType, Percent |
| Shield | Amount |
| DoT | TickDamage, TickInterval, DamageType |
| HoT | TickHeal, TickInterval |
| StatMod | Stat, ModType, Value |

### 2.2.3 叠加规则定义

| 规则 | 行为 | 适用场景 |
|------|------|---------|
| **Replace** | 新效果替换旧效果（刷新持续时间和参数）| 大多数 CC（减速、眩晕）|
| **Stack** | 效果叠加层数，直到 MaxStacks | DoT（灼烧叠3层）、StatMod（攻速叠加）|
| **Refresh** | 保持当前参数，只刷新持续时间 | 眩晕刷新（不重新计算免疫递减）|
| **Independent** | 完全独立的多个实例 | 不同来源的伤害 |

### 2.2.4 互斥组规则

同一个 `MutexGroup` 内的效果互斥：
- 新效果会替换旧效果（无论叠加规则如何）
- 典型用例：`MutexGroup = "HardCC"` — 眩晕/击飞/石化互斥，后施加的覆盖先施加的

### 2.2.5 CC 子类型定义

| CCType | 效果 | 可移动 | 可施法 | 可普攻 |
|--------|------|--------|--------|--------|
| Stun | 眩晕 | ❌ | ❌ | ❌ |
| Slow | 减速 | 🔻 | ✅ | ✅ |
| Root | 定身 | ❌ | ✅ | ✅ |
| Knockup | 击飞 | ❌ | ❌ | ❌ |
| Silence | 沉默 | ✅ | ❌ | ✅ |
| Disarm | 缴械 | ✅ | ✅ | ❌ |

### 2.2.6 效果 ID 分配方案

| ID 范围 | 用途 |
|---------|------|
| 3001-3019 | 拉克丝(Lux)技能效果 |
| 3020-3039 | 安琪拉(Angela)技能效果 |
| 3040-3059 | 后羿(HouYi)技能效果 |
| 3060-3079 | 廉颇(LianPo)技能效果 |
| 3080-3099 | 预留（赵云等新英雄） |
| 3900-3949 | 通用效果（装备/符文/地图机制）|
| 3950-3999 | 调试/测试效果 |

## 2.3 模块C: BuffSystem 运行时管理

### 2.3.1 核心职责

BuffSystem 是效果的运行时管理器，负责：

| 职责 | 说明 |
|------|------|
| **添加效果** | 根据 EffectConfig 创建 Buff 实例 |
| **移除效果** | 手动移除或到期自动移除 |
| **叠加处理** | 根据 Stacking 规则处理重复施加 |
| **互斥检查** | 根据 MutexGroup 处理互斥覆盖 |
| **持续时间管理** | Heartbeat 驱动，检查到期并清理 |
| **Tick 效果** | DoT/HoT 按 TickInterval 执行 |
| **属性修改** | StatMod 效果的施加和恢复 |
| **查询接口** | 查询角色身上的 Buff 列表/是否有某类 Buff |

### 2.3.2 Buff 实例数据结构

每个活跃 Buff 实例包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| instanceId | string | 唯一实例 ID |
| effectId | number | 引用 EffectConfig 的效果 ID |
| source | Model | 施加者的 Character |
| target | Model | 承受者的 Character |
| startTime | number | 施加时刻（os.clock()）|
| duration | number | 持续时间（秒）|
| stacks | number | 当前叠加层数 |
| lastTickTime | number | 上次 Tick 时间（DoT/HoT 用）|

### 2.3.3 核心 API

| 方法 | 参数 | 说明 |
|------|------|------|
| ApplyEffect | (source, target, effectId) | 核心入口：根据 EffectConfig 施加效果 |
| RemoveEffect | (target, effectId) | 移除指定效果 |
| RemoveAllEffects | (target) | 移除目标所有效果（死亡/重置时）|
| HasEffect | (target, effectId) → boolean | 查询是否有指定效果 |
| HasCCType | (target, ccType) → boolean | 查询是否被某种 CC 控制 |
| GetBuffStacks | (target, effectId) → number | 获取叠加层数 |
| GetActiveBuffs | (target) → table | 获取所有活跃 Buff 列表 |

### 2.3.4 执行流程

```
ApplyEffect(source, target, effectId)
    │
    ├── 1. 读取 EffectConfig[effectId]
    │
    ├── 2. 互斥组检查
    │   └── 有同组 Buff? → 移除旧的
    │
    ├── 3. 叠加规则处理
    │   ├── Replace → 移除旧实例，创建新实例
    │   ├── Stack → 增加 stacks（不超 MaxStacks），刷新时间
    │   ├── Refresh → 保持参数，只刷新 duration
    │   └── Independent → 创建新独立实例
    │
    ├── 4. 执行即时效果
    │   ├── Damage → 调用 Humanoid:TakeDamage()
    │   ├── Shield → 创建 ForceField + ShieldAmount Attribute
    │   └── StatMod → 修改 WalkSpeed / 其他 Attribute
    │
    ├── 5. CC 效果施加
    │   ├── Stun/Knockup → Anchored=true + 禁用输入
    │   ├── Slow → WalkSpeed *= (1 - Percent)
    │   ├── Root → Anchored=true（可施法）
    │   ├── Silence → 禁止技能（canCastSkill=false）
    │   └── Disarm → 禁止普攻（canAutoAttack=false）
    │
    └── 6. 注册到 activeBuffs，由 Heartbeat 管理生命周期
```

### 2.3.5 Heartbeat 驱动的生命周期管理

**不使用 task.delay**，改为 RunService.Heartbeat 统一驱动：

每帧检查：
1. 遍历 `activeBuffs` 中所有角色的所有 Buff
2. 对有 Tick 的 Buff（DoT/HoT），检查是否到达 TickInterval，是则执行 Tick
3. 检查 duration 是否到期，是则移除 Buff 并恢复效果
4. Shield Buff：检查 ShieldAmount Attribute 是否降为 0，是则提前移除

**性能考量**:
- 当前最多 10 个角色（5v5），每角色最多 ~10 个活跃 Buff
- 每帧检查 ~100 个 Buff，在 Roblox Luau 中完全无压力
- 后续如有性能问题，可改为脏标记 + 批量处理

### 2.3.6 效果清理机制

| 触发条件 | 清理行为 |
|----------|---------|
| Buff 持续时间到期 | 自动移除，恢复所有修改的属性 |
| 角色死亡 | RemoveAllEffects，清除所有 Buff |
| 角色重生 | 确保干净状态，无遗留 Buff |
| Shield 被击碎 | ShieldAmount ≤ 0 时提前移除 |
| CC 被净化（未来功能）| 预留 RemoveByTag("CC") 接口 |

## 2.4 数值设计

### 2.4.1 现有 15 技能的效果提取

以下是从现有技能代码中提取的效果列表（用于 EffectConfig 初始数据）：
