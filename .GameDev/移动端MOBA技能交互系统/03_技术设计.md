### 1.2 技术建议

| # | 建议 | 说明 |
|---|------|------|
| T1 | StatsBinding 不需要新建 InitMobile 方法 | 现有 `Init(hud)` 是参数化设计，传入实现了相同接口的 MobileHUD 适配对象即可。但 MobileHUD 的属性名与 PC HUD 不同，需要一个**轻量适配层** |

### 3.2 核心模块设计

#### 🆕 SkillIndicatorManager (新建)

**职责**: 管理 3D 世界中的技能范围指示器，包含对象池、显示/隐藏/旋转/动画。

**设计原则**: 纯渲染模块，不包含任何业务逻辑（不判断CD/蓝量/状态）。由 UI_SkillButtons 驱动。

**InitMobile 设计说明**:

现有 `Init(hud)` 依赖 `hudRef.HpFill`/`HpText`/`MpFill`/`MpText`/`StatLabels`/`LevelText`/`XpFill`/`XpText` 这8类UI引用。

`UI_MobileHUD` 只有 HP/MP/Level 三个维度的 API（没有战斗属性面板、没有经验条），因此不能直接传入。

**方案**: `InitMobile(mobileHUD)` 创建一个**适配对象**，将 MobileHUD 的 Update 方法包装为与 PC HUD 兼容的接口格式：

```lua
-- InitMobile 内部创建适配层
local adapter = {
    HpFill = { Size = ... },     -- 由 MobileHUD.UpdateHP 驱动
    HpText = { Text = "" },
    MpFill = { Size = ... },     -- 由 MobileHUD.UpdateMP 驱动
    MpText = { Text = "" },
    LevelText = { Text = "" },   -- 由 MobileHUD.UpdateLevel 驱动
    StatLabels = {},              -- 空表(移动端不显示战斗属性)
    XpFill = nil,                 -- 移动端不显示经验条
    XpText = nil,
}
```

但这样需要重构 `updateHP`/`updateMP` 内部逻辑来兼容nil字段，增加复杂度。

**更简洁的方案**: `InitMobile` 不走适配层，而是直接监听 Character Attributes 并调用 `mobileHUD.UpdateHP()`/`UpdateMP()`/`UpdateLevel()`。代码更直观，与现有 `Init(hud)` 逻辑平行但独立。

✅ **采纳方案2**: InitMobile 内部直接监听 Attributes → 调用 MobileHUD API。代码约 60 行，与 Init 逻辑平行。
