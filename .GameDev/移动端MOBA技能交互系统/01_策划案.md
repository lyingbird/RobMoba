# 第一章 功能概述

移动端玩家进入训练场/战斗后，使用完全独立于PC端的移动端专用UI布局和技能交互系统，提供符合MOBA手游体验标准的操作手感。

**王者荣耀参考**: 王者荣耀的移动端技能交互是手游MOBA的黄金标准——右侧弧形技能按钮、按住拖拽瞄准、松手释放、拖回取消。本方案以此为基础，结合Roblox平台特性做适配。

## 1.1 设计目标

| 目标 | 描述 | 优先级 |
|------|------|--------|
| G1: 移动端UI独立 | 移动端进入战斗后使用 MobileHUD（顶部信息栏） + SkillButtons（技能按钮面板） + VirtualJoystick（虚拟摇杆），**完全不显示PC端HUD** | P0 |
| G2: 指示器瞄准系统 | 技能按住拖拽时显示对应类型的指示器（方向线/扇形/范围圈/自身圈），实现"所见即所得"的瞄准反馈 | P0 |
| G3: 交互状态机 | 技能按钮有完整的状态机（IDLE→AIMING→RELEASING→COOLDOWN），状态切换逻辑清晰、无卡死 | P0 |
| G4: 取消机制 | 拖拽返回按钮范围内松手可取消技能释放，防止误操作 | P0 |
| G5: 蓄力系统预留 | 架构上预留蓄力（Charge）扩展点，当前英雄不需要蓄力但未来可能增加 | P2 |

## 1.2 用户故事

作为一个 **移动端MOBA玩家**，
我想要 **按住技能按钮时看到瞄准指示器，拖拽调整方向/位置后松手释放技能**，
以便 **像王者荣耀一样精准地释放每个技能，享受流畅的MOBA操作手感**。

作为一个 **移动端玩家**，
我想要 **进入训练场后看到移动端专用的UI布局（顶部信息栏、右侧技能面板、左侧摇杆）**，
以便 **不被PC端HUD干扰，获得为触屏优化的操作界面**。

# 第二章 功能详细设计

## 2.1 移动端UI布局切换

### 2.1.1 核心机制

移动端进入战斗时，**禁止初始化PC端HUD**，改为初始化移动端专用UI组件。

**当前流程（有问题）:**
```
initMobileCombatUI()
  → UIManager.Init()           ← 这里会创建PC端HUD！
    → UI_HUD.Init()            ← PC技能栏、属性面板、VS比分
    → UI_Backpack.Init()
    → UI_DragDrop.Init()
    → UI_MatchButton.Init()
  → UI_VirtualJoystick.Init()
  → UI_SkillButtons.Init()
  → MobileInputManager.Init()
```

**目标流程:**
```
initMobileCombatUI()
  → UIManager.InitMobileOnly()    ← 新方法：跳过UI_HUD，只初始化移动端需要的
    → UI_MobileHUD.Init()         ← 移动端顶部信息栏
    → UI_MatchButton.Init()       ← 匹配按钮（复用）
  → UI_VirtualJoystick.Init()     ← 虚拟摇杆（已有）
  → UI_SkillButtons.Init()        ← 技能按钮面板（已有，需升级）
  → MobileInputManager.Init()     ← 输入管理（已有）
  → StatsBinding.InitMobile()     ← 新方法：绑定属性到MobileHUD而非PC HUD
```

**布局说明（参考王者荣耀）：**
- **顶部**: MobileHUD TopBar（等级、HP条、MP条、计时器、比分）
- **左下**: 虚拟摇杆（已有）
- **右下**: 技能按钮弧形排列（已有，Q/W/R/Attack/D/F）
- **中间**: 纯净游戏视野，技能指示器在3D世界中渲染
- **底部**: 预留系统安全区

### 2.1.3 PC端HUD隐藏策略

移动端不创建而非隐藏PC端HUD——`UIManager` 需新增 `InitMobileOnly()` 方法，该方法：
1. **不调用** `UI_HUD.Init()` — 不创建PC技能栏、属性面板、VS比分
2. **不调用** `UI_Backpack.Init()` — 移动端不使用背包UI
3. **不调用** `UI_DragDrop.Init()` — 移动端不使用拖拽装备
4. **调用** `UI_MobileHUD.Init(parentFrame)` — 初始化移动端HUD
5. **调用** `UI_MatchButton.Init()` — 匹配按钮可复用

## 2.2 技能指示器系统

### 2.2.1 指示器类型定义

Phase 1 实现以下 3 种指示器（+ 1 种无指示器类型）：

| 指示器类型 | 外观描述 | 触屏交互 | 适用 aimType | 王者荣耀参考 |
|-----------|---------|----------|-------------|-------------|
| **LINE** | 从英雄脚下延伸的方向线（长度=技能Range），半透明带箭头 | 按住拖拽旋转方向 | `"directional"` + 未定义aimType | 后羿大招、安琪拉Q/W方向指示 |
| **CIRCLE_SELF** | 以英雄为中心的圆形范围（半径=技能Range），脉冲边缘 | 点按即放，无需拖拽瞄准 | `"self"` | 后羿Q自身增益、廉颇W自身护盾 |
| **CIRCLE_DROP** | 可拖拽定位的落点圆圈（半径=AreaRadius），从英雄到落点有连线 | 按住拖拽移动落点位置 | `"area"` | 后羿W落点选择、Lux E透光奇点 |
| **NONE** | 无指示器 | 点按即放 | `"channel"` | 安琪拉R引导（开始引导后由服务端控制） |

> 💡[假设] SECTOR扇形指示器当前4个英雄不需要，Phase 3 再实现。

### 2.2.2 指示器渲染方案

**渲染层级**: 在3D世界中使用 `Part`+`Decal`/`Beam` 渲染指示器，而非2D UI。

**理由（王者荣耀做法）：**
- 指示器需要贴合地面，反映实际技能范围
- 2D指示器无法准确表达3D空间中的距离和方向
- Roblox Workspace 中的 Part 天然支持和游戏世界对齐

#### LINE 指示器

| 组件 | 实现 | 参数 |
|------|------|------|
| 方向线本体 | `Part(Neon材质, 薄片形状)` 或 `Beam` | 长度=SkillRange, 宽度=1.5 stud, 颜色=英雄主色(半透明) |
| 箭头 | 方向线末端三角形装饰 | 宽度=3 stud |
| 范围边界 | 方向线两侧淡色边线 | 宽度=技能宽度(如果有) |
| 起始圆 | 英雄脚下小圆环 | 半径=2 stud |

**更新逻辑**: 每帧根据拖拽方向更新旋转角度（`CFrame.lookAt`）

#### CIRCLE_SELF 指示器

| 组件 | 实现 | 参数 |
|------|------|------|
| 范围圆 | `Part(圆柱, Neon材质, 扁平)` | 半径=SkillRange, 高度=0.1, 颜色=英雄主色(半透明) |
| 脉冲动画 | `TweenService` 循环缩放 | 周期=1秒, 缩放范围=0.95~1.05 |

**更新逻辑**: 锁定在英雄 HumanoidRootPart 下方，按下即显示，松手后1帧消失

#### CIRCLE_DROP 指示器（Phase 2 但架构预留）

| 组件 | 实现 | 参数 |
|------|------|------|
| 落点圆 | `Part(圆柱, Neon材质, 扁平)` | 半径=SkillRadius, 高度=0.1, 颜色=技能色(半透明) |
| 连接线 | 英雄→落点的虚线 | Beam + TextureLength 实现虚线效果 |
| 范围边界 | 外围最大距离圆环 | 半径=SkillRange, 虚线描边 |

**更新逻辑**: 拖拽方向+距离 → 映射为世界坐标落点（clamped to MaxRange）

### 2.2.3 指示器生命周期

```
技能按钮 TouchBegan
  → 创建指示器实例（对象池复用）
  → Visible = true
  → 开始每帧更新

拖拽中 (TouchMoved)
  → 更新指示器朝向/位置

松手释放 (TouchEnded, 非取消区)
  → 指示器播放"释放闪光"动画 (0.15秒)
  → 销毁/回收指示器

松手取消 (TouchEnded, 在取消区)
  → 指示器播放"消散"动画 (0.1秒)
  → 销毁/回收指示器

CD中
  → 指示器不存在
```

### 2.2.4 现有 UI_SkillButtons 方向轮与指示器的关系

当前 `UI_SkillButtons` 已有 2D 方向轮（`aimLine` Frame），用于在按钮上显示拖拽方向。

**策略**: 保留2D方向轮作为**按钮端反馈**，同时在3D世界中渲染**真正的指示器**。

| 反馈层 | 渲染位置 | 用途 |
|--------|---------|------|
| 2D方向轮(aimLine) | 技能按钮上 | 手指拖拽的直接反馈（保留现有功能） |
| 3D指示器 | 游戏世界地面 | 技能实际影响范围的精准预览 |

两者同步更新方向，玩家同时看到按钮端和世界端的瞄准反馈。

## 2.3 技能交互状态机

### 2.3.1 状态定义

| 状态 | 含义 | 进入条件 | 可转移目标 |
|------|------|----------|-----------|
| **IDLE** | 空闲可用 | 初始状态 / CD结束 / 取消释放 / 释放完成 | AIMING, INSTANT_CAST |
| **INSTANT_CAST** | 即时释放（self/channel类型） | IDLE状态 + TouchBegan + aimType为self/channel | COOLDOWN |
| **AIMING** | 瞄准中（显示指示器） | IDLE状态 + TouchBegan + aimType为directional/area | RELEASING, CANCEL |
| **CANCEL** | 取消（拖回取消区） | AIMING状态 + TouchEnded + 在取消区内 | IDLE |
| **RELEASING** | 释放中（发送到服务端） | AIMING状态 + TouchEnded + 不在取消区 | COOLDOWN |
| **COOLDOWN** | CD冷却中 | INSTANT_CAST/RELEASING 后 | IDLE (CD到期) |
| **DISABLED** | 被控制/沉默 | 收到CC效果 | IDLE (CC结束) |
| **DEAD** | 死亡状态 | 角色死亡 | IDLE (复活) |
| **NO_MANA** | 蓝量不足 | 蓝量 < 技能消耗 | IDLE (蓝量回复) |

### 2.3.2 状态转移图

```
                    TouchBegan (self/channel)
            ┌──────────────────────────────────────┐
            │                                      ▼
         ┌──────┐   TouchBegan (dir/area)   ┌─────────────┐

    │    └──────┘                            └──────┬──────┘
    │       ▲                                       │
    │       │                              ┌────────┴────────┐
    │       │                              │                  │
    │  ┌────┴─────┐   TouchEnded       TouchEnded         TouchEnded
    │  │  CANCEL  │◀─── (取消区)       (非取消区)          (非取消区)
    │  └──────────┘                        │                  │
    │                               ┌──────▼──────┐   ┌──────▼──────┐
    │                               │ INSTANT_CAST│   │  RELEASING  │
    │                               └──────┬──────┘   └──────┬──────┘
    │                                      │                  │
    │                                      ▼                  ▼
    │                               ┌─────────────────────────────┐
    └───────────────────────────────│         COOLDOWN             │

    任意状态 ──死亡────▶ DEAD ────复活─────▶ IDLE
    IDLE ─────蓝不足──▶ NO_MANA ──蓝回复──▶ IDLE
```

### 2.3.3 状态与视觉反馈映射

| 状态 | 按钮外观 | 3D指示器 | 2D方向轮 |
|------|---------|---------|---------|
| IDLE | 正常显示 | 不存在 | 不存在 |
| INSTANT_CAST | 按下缩放(0.1秒) → 恢复 | CIRCLE_SELF闪现 → 消失 | 不显示 |
| AIMING | 边框发蓝光 | LINE/CIRCLE_DROP 可见并跟随拖拽 | 显示 aimLine |
| CANCEL | 边框变红 | 指示器变红半透明 → 消散 | 显示 ✕ 标记 |
| RELEASING | 短暂白色闪光 | 指示器闪光 → 消失 | 消失 |
| COOLDOWN | 灰色遮罩 + 秒数 | 不存在 | 不存在 |
| DISABLED | 暗淡 + 🔒 | 不存在 | 不存在 |
| DEAD | 全暗(0.8透明度) | 不存在 | 不存在 |
| NO_MANA | 暗淡 + 蓝色边框 | 不存在 | 不存在 |

### 2.3.4 与现有 UI_SkillButtons 状态的对应关系

现有 `UI_SkillButtons` 已有8种按钮状态（Idle/Pressed/Aiming/Cooldown/Ready/NoMana/Disabled/Dead），与新状态机的对应：

| 新状态机 | 现有按钮状态 | 需要变更 |
|----------|------------|---------|
| IDLE | Idle | ✅ 兼容 |
| INSTANT_CAST | Pressed | ✅ 兼容（已有按下缩放） |
| AIMING | Aiming | ✅ 兼容（已有蓝色发光+方向轮） |
| CANCEL | (新增) | ⚠️ 需新增：红色边框 + ✕ 标记（现有 aimCancelMark 可复用） |
| RELEASING | (新增) | ⚠️ 需新增：白色闪光短暂反馈 |
| COOLDOWN | Cooldown | ✅ 兼容 |
| DISABLED | Disabled | ✅ 兼容 |
| DEAD | Dead | ✅ 兼容 |
| NO_MANA | NoMana | ✅ 兼容 |

**结论**: 8个现有状态中6个直接兼容，只需新增 CANCEL 和 RELEASING 的视觉表现。

## 2.6 边界条件与异常处理

### 2.6.1 交互边界

| 场景 | 处理方式 |
|------|---------|
| 技能CD中按下按钮 | 忽略触摸，按钮保持COOLDOWN状态不变 |
| 蓝量不足时按下按钮 | 忽略触摸，按钮短暂抖动（shake动画0.2秒） + NO_MANA状态 |
| 被控制时按下按钮 | 忽略触摸，DISABLED状态不变 |
| 死亡时按下按钮 | 忽略触摸，DEAD状态不变 |
| 瞄准中角色被控制 | 强制取消当前瞄准 → AIMING→CANCEL→DISABLED |
| 瞄准中角色死亡 | 强制取消当前瞄准 → AIMING→CANCEL→DEAD |
| 两根手指同时按两个技能 | 只响应第一个触摸，第二个忽略（全局aimingSlot锁） |
| 拖拽出屏幕边界 | 方向保持最后有效值，松手视为释放（非取消） |
| 引导技能中再次按按钮 | 安琪拉R引导中无法使用其他技能（引导期间全局锁定） |

### 2.6.2 性能边界

| 场景 | 处理方式 |
|------|---------|
| 指示器更新帧率 | 绑定 `RunService.RenderStepped`，每帧更新 |
| 指示器Part数量 | 每个指示器最多3个Part（主体+装饰+起始圆），总共不超过10个Part |
| 指示器对象池 | LINE和CIRCLE_SELF各预创建1个实例，显示/隐藏切换而非创建/销毁 |
| 同时存在指示器数 | 最多1个（同一时间只能瞄准一个技能） |

### 2.6.3 与现有系统的兼容性

| 关联系统 | 影响 | 策略 |
|---------|------|------|
| PC端HUD (`UI_HUD`) | 移动端不再初始化 | UIManager 分支：PC走Init()，移动走InitMobileOnly() |
| PC端InputManager | 移动端不使用 | 保持现有分支逻辑不变 |
| SkillSystem（服务端） | 技能释放接口不变 | 客户端只改瞄准和指示器，FireServer参数格式不变 |
| MovementController | 不受影响 | 指示器不影响移动逻辑 |
| CameraManager | 不受影响 | 已有 SetMobileMode 切换 |
| StatsBinding | 需适配MobileHUD | 新增 InitMobile() 方法绑定到 UI_MobileHUD 而非 UI_HUD |
